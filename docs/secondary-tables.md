# Secondary tables

Primary Browse and embedded sections with multiple presentations share `BrowseToolbar` and the keyboard-scrollable `TableScroll` primitive. Embedded tables compose the table components in `apps/web/components/secondary-table.tsx` and use the raw-value comparator in `apps/web/utils/secondary-table.ts` for complete local datasets.

## Interaction

- Every data header is a button that switches between ascending and descending order. The active header exposes `aria-sort` and a direction arrow. Selection, artwork and action-only columns have no sort button.
- Tables with more than three available columns offer **Columns** to show or hide columns and **Reset columns** to restore defaults. Choices are saved independently for each table in this browser. Essential identity or selection controls can remain fixed; at least one configurable column stays visible. Invalid or unavailable browser storage falls back to usable defaults. Tables with three or fewer columns have no chooser and show every column, including fields previously hidden by defaults or saved preferences. `useTableColumns(id, columns, { reorder: true })` adds a drag handle to each entry of the chooser (also moved with the Up and Down keys) and **Reset order**; the order is saved with the table's other choices. Pass a table's cells through its `order()` so headers and cells move together. A table that renders its cells one by one leaves `reorder` off.
- Every table has set column widths, so rows that are still loading never move the columns. Each data column has a default width and a handle on the right edge of its header: drag it, or focus it and use the Left and Right keys, to change the width, and double-click it to return to the default. Widths are saved independently for each table in this browser, and **Reset columns** restores them with the other column choices. Selection columns and columns of one small row action keep a fixed width and have no handle. Every column keeps its width except one, which takes the room that is left and is never narrower than its own width: the identity column where the last column is a number, a date or a status, otherwise the last data column. A table wider than its panel scrolls sideways.
- Numeric values sort numerically, dates by their underlying timestamps, and text case-insensitively. Missing values sort last in either direction. Metadata freshness retains its existing never-scraped-first ascending order. Use a stable tie-breaker for paginated server queries.
- Search, filter and sort the entire dataset before pagination. Server-backed lists send these controls to their API; never filter or reorder only loaded pages. Changing search, filters or sort resets pagination and scrolling, and clears selection where the action depends on the displayed rows or order. Local import previews filter and sort the entire preview before rendering their first batch.
- Every paginated table, list and detail section uses the [Browse pagination behavior](requirements/browsing.md). Keep a viewport of same-size placeholders while the initial count is pending. Once the count is known, reserve the full result height. Scroll directly to any position and fetch only the pages near it. Keep placeholders and the scrollbar in place after a failed page and offer Retry. A complete local dataset can use the same viewport without issuing page requests.
- Audit the transport as well as the renderer: server-backed directories such as Collections must never fetch an entire array and slice it locally. A bounded virtual DOM does not make an unbounded network request acceptable. Apply search and sort on the server, cap page sizes and resolve source payloads only for the returned page when requested.
- Nested albums, tracks, films and related media offer Grid, List and Table while retaining their filters, sort and panel navigation. Use the same `BrowseToolbar` as the main library. Keep the sort field and compact ghost direction button available in all three views. Put available filters in the common Filters drawer and use its Columns section for configurable table columns. Reuse the same virtual page window, matching placeholders to its current card or row geometry. Presentation choices are independent of the main library's view preference. Track lists start in Table and album and film lists in Grid (`defaultBrowseView`). The Grid view shows the density control after the view switch; the density is kept per artwork shape (`useNestedGridDensity`) and `useVirtualTable` sizes the cards from it.
- Column visibility changes headers, cells and loading/error/expanded-row spans together. Horizontal scrolling keeps chosen columns available on small screens; do not silently hide them with responsive CSS.
- Tables use a labelled, keyboard-scrollable region, compact cells and sticky headers. Match primary Browse with no outer table frame, rounded row boxes or divider below the search/filter toolbar. Retain the normal row and column-header separators and the visible keyboard focus outline. Keep loading, empty, failure and retry states inside the same table structure where possible. Preserve range selection, explicit bulk actions, job detail navigation and provider request limits.

## Toolbar and filters

Table-only views use the design-system `Toolbar` immediately above the table: actions, `SecondaryTableSearch` (the `ds-search` field), `ToolbarCount` ("12 albums", "6 of 128 albums" through `formatItemCount`), then Columns in `ToolbarEnd`, which keeps its own upper-right slot even when controls wrap. `SecondaryDataTable` builds this toolbar itself; other tables pass their search, count and columns to `SecondaryTableToolbar`, which renders the same `Toolbar` and closes open `details.browse-popover` popovers on Escape or an outside click. Table-wide actions, such as listing a source again or starting a new import, belong above this toolbar. Metadata selection uses `MetadataSelectionToolbar` for album, film and artist tables. It places active filter chips in a separate row above search, the count, Filters and Columns, with table-wide actions such as **Select all matching** after the count. Use Browse autocomplete and AI search with the table's freshness filters.

Put categorical filters beside their column's sort button using `SecondaryColumnFilter`. Always allow multiple values; an empty selection means all values. Values in one column match with OR; different filtered columns combine with AND. Use `SecondaryHeaderFilter` for a numeric/date range or other column-specific control. Filters open in the top layer so sticky headers and table overflow cannot clip them. Active filter buttons are highlighted. A hidden column's filter remains applied and is available by restoring that column with Columns.

Provide text search for lists of names, titles or jobs. Choose filters that answer a concrete question: job status/provider, new versus already imported preview rows, playlist source or import status, watched films, or subscription kind/history. Import previews must let users hide existing items; omit that filter when the preview already excludes them, as NFO previews do. Show matching counts; local previews can use `matching of total`. Preserve navigation filters such as Tags and Hidden tags. Active facet chips belong above the toolbar. A three-column summary needs neither a chooser nor redundant search controls.

Selectable tables have a tri-state checkbox in the first header. It selects eligible matching rows in a complete local dataset, or eligible loaded rows in a paginated server list. Its accessible label states the scope. Disabled and ineligible rows stay excluded. Unchecking clears the selection. If a workflow supports selecting the entire server result set, add **Select all matching** to the toolbar after the count and state how many rows it selected. The server must determine that selection from the active filters independently of the loaded pages. Verify the scope in the action review, clear it when the query changes and retain the existing provider limits and broad-run safeguards.

Wrap selectable tables in `SecondaryTableFrame`, with `SecondaryTableScroll` followed by the selection bar. Secondary tables use `SecondaryTableSelectionBar` (the design-system `ds-selectbar`: "2 selected of 128" on the left, actions after it, `Button` components restyled for the inverse surface); the jobs and metadata tables use `TableSelectionBar` directly. Put selection counts, row actions and their confirmations in this attached bar, outside the scroll area. The bar appears only while something is selected or an action has a result to report, so Jobs, Metadata and the Last.fm links table show no bar with nothing selected (the Last.fm links table through `hideWhenEmpty`). Import previews are the exception: they keep "0 selected of N". Preserve action review, queue limits and running-job safeguards. Table-wide actions stay above the toolbar; inline row-specific links and disclosure controls can remain in their cells.

**Column layout.** `DataColumn` and `SecondaryTableHead` accept `align: 'end'` for numbers and counts, as in People, Channels and creator detail tables, and `sticky`/`stickyEdge` to pin the selection and identity columns (selection at 0, identity at 36px). Plain values render through `formatTableValue`: counts with separators, an en dash for a missing value.

**Column widths.** Give every column a default `width` in pixels in its definition (`TableColumn.width`); a column without one gets 140. Choose it from what the cell renders: 36 for selection, about 56 for a row number, 80 to 100 for counts and durations, 110 for an ISO date, 120 to 150 for a status, provider or other short value, 180 to 220 for a secondary name, 260 to 320 for the identity column and for long text. Keep a full-page table's default columns within about 1150px and a table inside the detail inspector within about 560px. Mark the identity column `fill: true` when the last column is a number, a date or a status, so the spare room goes to the title; without one, the last data column takes it. A column of one small row action that is among the hook's columns takes `resizable: false`. `useTableColumns(id, columns)` returns `layout` and `resizer`; a table without a column chooser uses `useTableWidths(id, columns)` for the same pair. Pass `layout` the displayed columns in order, a key for each data column and a pixel width for each selection or action column, spread `layout.table` on the table and render `layout.colgroup` first inside it, and give each data column's header `resizer(key)`:

```tsx
const columns = useTableColumns('jobs', jobColumns)
const layout = columns.layout([
  selectionWidth,
  ...shownColumns.map((column) => column.key),
  actionsWidth,
])

<table className="ds-table" aria-label="Jobs" {...layout.table}>
  {layout.colgroup}
  <thead>
    <tr>
      <TableHead sticky={0}>…</TableHead>
      {shownColumns.map((column) => (
        <SecondaryTableHead … resizer={columns.resizer(column.key)} />
      ))}
      <TableHead align="end">…</TableHead>
    </tr>
  </thead>
```

The entries must match the header cells in every state of the table. `SecondaryDataTable` does this itself from each column's `width`. Primary Browse keeps its widths with `useColumnWidths` (`hooks/useColumnWidths.ts`), which both share; the limits and the layout arithmetic are in `utils/column-widths.ts`.

**Confirmations.** Broad runs and destructive actions use one pattern, `ConfirmAction`: a popover on the button that started the action with the question, what happens, the action and Cancel (for example "Import 12 albums? · Import · Cancel", "Revoke Example key? · Revoke · Cancel"). Below the broad-run threshold the button acts at once. It replaces the confirmation checkboxes on album, film, playlist and Spotify-search imports and the inline "Confirm …/Back" pairs.

Secondary workspaces, including Playlists and Film Collections, always fill the available content width. Do not impose a reading-width cap or allow a flex child to shrink to its intrinsic table width. The table takes the remaining page height and scrolls internally; the toolbar and selection bar remain available.

## Row density and cell details

Ordinary rows use one line of content. Use the shared `SecondaryCell` wrapper for clipped text and a bounded layout; long titles, names, identifiers, descriptions and result messages must not increase a row's height. A deliberately chosen two-line cell is the maximum exception. Keep artwork and controls within the same row height, and keep action groups on one line.

Keep the primary value readable in the row: a short status, title or result summary. Supply the full text for its tooltip. Put explanations, match strategies, import timestamps and counts, errors, warnings and field-by-field changes in the shared circled Info details popover. Do not show a details icon when it only repeats fully visible text. Clipped text may expose its full value; warnings use a warning triangle instead of Info. The popover must work on hover, keyboard focus and click/tap, escape the table's clipping, and remain readable without changing row height. Keep links and actions usable inside details; do not replace an action with inaccessible clipped text. Icon-only buttons require an accessible label and a tooltip.

The Jobs page and provider jobs use the same `JobsTable` and column preferences: Job (pinned), Status, Provider, Progress, Created, Started and Finished (hidden by default), Duration and Result, then the row action. Times show the clock time today and the ISO date before, with the full timestamp on hover. Job names open the shared details inspector; checkboxes select jobs for bulk actions without opening details. Overview, Request and response, and Logs live in the inspector, with per-entry tabs and parent history preserved. An item's or artist's job history is not a jobs table: it is the merged history list in each source row in Sources. Loading, empty and error rows retain enough space for their message and retry control. Do not apply the row limit to these states or to Browse.

The job monitor can list batches as single rows with `GET /api/v1/scrape/jobs/entries`. It takes the jobs list query; filters select jobs, and a batch of more than one job appears once when any of its jobs match. Its counts cover the whole batch, with `matching` for the jobs that matched. A batch of one stays a job row. Grouping, sorting and pagination run in SQL; a batch sorts by its earliest creation or start, its latest finish once complete, its derived status, or its smallest provider, title or result, and ties break on the job or batch ID. Expand a batch with the jobs list `batchId` filter. The Jobs page shows each batch as a group row (`TableRow group`) with a chevron that loads the first 25 matching jobs (`batchId` plus the active filters) as child rows; a longer batch links to its full list. Queued jobs and batches with nothing running carry the same `waiting` reason, for example `Waiting until 14:20` for a synthetic provider in cooldown.

## Components

`SecondaryDataTable` is for complete datasets already in memory. Define each column's raw `value` separately from its optional formatted `render`. Supply a stable row key and default sort. Its optional `search` supplies a label, placeholder and searchable row value; each column can supply a `filter` control, and callers apply those filters before passing `rows`. Use `countLabel` for the result-count noun and `totalCount` when reporting the original total of a filtered dataset. It renders the shared toolbar automatically and omits it when there are no useful controls or count.

Tables with custom selection, server pagination or expandable rows compose `SecondaryTableScroll`, `SecondaryTableHead` and `useTableColumns`, adding the frame and selection bar for selection, and take their fixed layout and width handles from the same hook. Use `SecondaryTableToolbar` with `SecondaryTableSearch`, the count and `useTableColumns().controls` for table-only views. For views with Grid, List and Table, use `BrowseToolbar` with a `BrowseColumnsSection` containing `useTableColumns().options` in Table. Pass column filters to the matching header and use the existing shared table primitives for rows and cells. The table-only column control is a native popover, closes on Escape and outside click and restores focus to its trigger on Escape.

Use `useVirtualTable` for server pages and `useVirtualRows` for progressively rendered local previews. Connect their scroller and scroll handler to `SecondaryTableScroll` and render the rows and placeholders with `SecondaryVirtualRows`. Use the row’s absolute index for displayed order and accessible row positions. An expanded row can report its extra height so it remains correctly represented after it leaves the viewport. A saved provider search shows its saved slice and explicit search controls, even if the snapshot includes a total. Viewing or scrolling saved data does not fetch further provider pages; an explicit new search can enable remote paging.

Make changes to controls shared by primary and embedded Browse in `BrowseToolbar` and its styles. Keep table-only styling scoped to the secondary wrapper.

Detail drawers use `MediaInspector` for a shared remembered desktop width. Drag the left edge or focus its separator and use Left/Right, Home/End (Shift for larger steps). Phone drawers remain full width.

Recent import history covers the latest 20 runs returned by the status endpoint. Its search, filters and headers operate on that explicitly recent set. Other paginated views filter and sort on the server across all matching results.

## Date and position meanings

Spotify playlist **Added to library** is the first stored library date. It is unknown for playlists not yet imported. Spotify's listing does not supply the date a playlist was followed/saved; do not invent that date or substitute last checked. Playlist entry **Added** is the stored membership date, when available.

Playlist entries default to stored position. Film collections also preserve stored positions and gaps; some older imports lack the original source ranking. Sorting another column does not renumber positions. See [film collections](film-collections.md).

## Verification

Use synthetic fixtures, mocked providers and disposable databases. Cover both sort directions, missing values, numeric/date ordering, ties across page boundaries, filtering before pagination, visible-column spans, selection after searching/filtering/reordering and original position labels. Verify that import filters can hide already imported rows and that tiny tables retain every column without a chooser.

Capture and visually inspect primary Browse and the equivalent embedded views side by side, including List, Grid and Table. Check the whole container, toolbar-to-content boundary and row outlines, not just control dimensions or DOM structure. Inspect the whole page in the browser at desktop and phone widths, with filters, Columns and cell details open as well as closed. Use synthetic long titles, many identifiers, verbose errors, multiple warnings and large change sets, then measure ordinary row heights; they must remain within the chosen one- or two-line limit. Check full workspace width, control order and height, Columns at the upper right, selection bar contrast and visibility, table scrolling and menu clipping; isolated component markup does not catch styles inherited from page ancestors. Verify column persistence, reset, Escape/outside dismissal and restored focus. Delay the rows and confirm that the header and columns do not move as they arrive; drag a width handle, reload and confirm the width is kept; confirm Reset columns restores it. Verify multi-value filters, eligible header selection and clearing, and drawer resizing/persistence with pointer and keyboard. Confirm full text and actions remain accessible after clipping, and opening a job reveals its complete diagnostics in the detail tabs. Sorting, filtering, hiding columns and opening stored details must never scrape, import, retry or play anything.

With a large synthetic total, drag the scrollbar straight to the end and confirm that only nearby pages were read. Check the row placeholders while the count and page responses are delayed independently, then confirm the scrollbar extent remains stable after the total is known. Change the query during a request, retry a failed window and verify that a selected row stays available to actions after it scrolls away.
