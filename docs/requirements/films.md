# Films

## Film metadata

Preserve title, source, poster, synopsis, awards, directors, actors, writers, countries, languages, production companies, tags, collections, watched state and external links. Numeric fields are release date, personal IMDb rating, IMDb rating/votes, Metascore, TMDb rating/votes/popularity, Rotten Tomatoes rating, runtime, budget and box office. Local plugins may contribute additional ratings/votes and collections. Default order is release descending.

## Requirements

- FILM-01: Account for every cleaned film row and reconcile raw entries by identifier without losing snapshots. Preserve identifiers, source hints, owned status, watched/rating/watchlist state and provider metadata. Raw duplicate records must not erase fields from another record.
- FILM-02: Source filters preserve the original categories and counts. Ownership/file sources take precedence over discovery/watchlist sources unless the cleaned input or a manual override says otherwise. Do not treat every imported film as the same source or leave a known source blank.
- FILM-03: Every textual field is available in overview/metadata and clickable where filterable. Every numeric field above is available in column selection, sorting and ranges, even when absent from the default table. Plugin-defined metrics are registered dynamically.
- FILM-04: IMDb/TMDb and plugin-supplied outbound links are available. Film cards remain poster-first; synopsis, cast and technical details do not overwhelm the browse grid.
- FILM-05: Preserve personal ratings without confusing them with public ratings. Display watched and bookmarked/watchlist information distinctly. Missing data is not zero or unwatched by inference.
- FILM-06: Added is available in sorting, table columns, date ranges and film details. NFO-backed films use the actual file creation timestamp (`birthtime`), never XML `dateadded`, modification/change time, or import time. Verified NFO creation time takes priority over other imported dates; manual overrides take highest priority. Preserve displaced dates and their provenance in history. Expose the NFO path in Overview. Repairing incorrect NFO provenance may move a date forward; other-source re-imports must not replace a verified NFO timestamp. Missing creation timestamps remain unknown rather than guessed. Historical repairs require a dry run, database backup, unique path/identifier matching, and transactional before/after history. If no historical evidence exists, the display may use the immutable database import time explicitly labelled original date unknown. Users can correct Added under Edit.
- FILM-07: Import TMDb and MDBList keywords without losing the original token, upstream source or identifier. Tags is one concept across genres and keywords: one filter, search, detail section and management view, including film selection. Original kinds are provenance only. Equivalent normalized names across kinds share counts and matches; old genre/keyword URLs remain compatible. Explicit merges within the film library retain provenance and persist across subsequent imports. The Tags page shows actual merged names, previews the target before merging, and exposes paginated source links without opening a film. Do not automatically merge merely related concepts.
- FILM-07a: Film tags list genres first, then keywords alphabetically, then year and decade tags, so cards and details lead with the genres. A tag is a genre when it is stored as one or any provider reported it as one.

- FILM-08: Keep audience scores separate from critic and personal ratings. Show each source’s native scale and vote count, distinguishing zero from unknown. Grid, table and detail rating links open independently of item details. Prefer a verified film URL; label a source-homepage fallback rather than guessing a slug. See [audience rating scales and links](../film-keyword-providers.md#audience-ratings).
- FILM-09: Films has a [Collections](../film-collections.md) tab listing stored collections with library-film counts. Opening one shows its films in stored position order and preserves gaps; ties have stable ordering. Do not invent source ranks for older records that did not store them. Collection and member tables support sorting and column visibility, with member sorting applied before pagination. Opening collections only reads stored data.

## Acceptance

Reconcile title, release date, source, watched, ratings, tags, credits and collections for every cleaned input row. Compare source-category counts. Use fixture films from different source categories, including a synthetic plugin snapshot. Verify imported links and labels come from the data, not hardcoded provider names.
