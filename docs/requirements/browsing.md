# Browsing and navigation

## Requirements

- BROWSE-01: Albums, Tracks, Artists, Films, Subscriptions and Mixes each support a table, compact list and image-first grid. Albums, Films, Subscriptions and Mixes start in Grid, Tracks in Table and Artists in List. A view named in the URL wins. A view saved before these defaults applied (before Tracks started in Table) is discarded once for Albums, Films and Tracks, so the new default shows; a view chosen afterwards is kept. Text is high contrast and dividers are subtle. Tags are pills that add a filter. Each view shows the first few and a `+N` count; pills are never clipped or scrolled. Album and track cards show two, the narrower artist and film cards one, list rows three and table cells two. Artist tags shown in place of missing album tags use the outline pill. Artists uses the Tracks Browse controls and behavior, including full autocomplete and AI search, field filter modes, ranges, sorting and independent count/page loading.
- BROWSE-02: Keep library navigation, universal search, sorting, sort direction, view toggle and result count close together, in that order: search, sort, direction, view, Filters, count. The sort control is a button of fixed width that names the field and opens every sortable field under a search field: typing narrows the list, Enter picks the first match and Escape closes it; a long field name is cut short on the button and shown in full on hover. On phones the field list is a sheet from the bottom edge. One Filters button opens the shared side panel (a drawer from the right, a sheet on phones; closed by its Close button, Escape or a click outside) for everything else: collapsible View, Columns (table), Smart playlists (albums), Ranges and Listening (albums, tracks and artists) sections. Inside a detail and on phones the button shows its icon and the number of filters that are on. Active filter chips stay in the navigation rail or mobile filter row.
- BROWSE-03: Every paginated grid, table, list and detail section reserves a viewport of placeholders while its initial total is unknown, then reserves the full matching result height. Scrollbar jumps request only the viewport and nearby pages. Keep count and visible page queries mounted, retain visited pages under the shared cache policy, and cancel obsolete reads. Reset on query changes, including same-count results. Use stable ordering with an ID tie-breaker. Failed pages keep their reserved space and offer Retry. When rows and count have separate endpoints, ready rows remain usable while counting or after a count failure. Scrolling to the end of a page with more results loads the next page. The last page establishes the matching total even if the count request fails.
- BROWSE-03a: Collection and item directories must be paginated at the API, even if an older endpoint returned an array. Apply search and sort over the full matching dataset before limiting each response. Exact counts travel separately when they would delay usable rows. Enrich only the returned page; a visible page must not trigger whole-directory payload expansion. Regression checks must assert bounded response size and requested pages as well as bounded DOM.
- BROWSE-03b: Nested media lists offer Grid, List and Table using the same dataset, filters, sorting and bounded page cache. Primary and embedded views use the shared Browse toolbar, sort controls and view switcher. Lists of tracks (a playlist's entries, an artist's tracks) start in Table; lists of albums and films (an artist's albums, a person's films, an album or film collection) start in Grid; other nested lists start in Table. Remember the choice independently for each nested list type; a choice stored under the earlier defaults is discarded once. Changing presentation must not fetch the remaining dataset or change what Play and Add to queue refer to. Placeholder geometry and full scroll extent must match the chosen presentation.
- BROWSE-03c: A list inside a detail that has the same items as a Browse page is that Browse list, held to the detail: an artist's albums and tracks, a person's films, a channel's items and a show's mixes. It has every control of its Browse page: the search with field suggestions and AI search, sorting by any field, filter modes, ranges, Listening filters where the library has them, Grid, List and Table, grid size, and column choice and order. The detail it is held to is not a filter: it shows no pill, is not counted, and neither Clear all nor an AI search removes it; the count is the detail's own (`34 tracks`). One line under the toolbar holds the active filters, the count and the link to Browse. The list's settings are part of the detail's URL, so Back, Open page and a copied link keep them, and changing tab clears them. The view, grid size, order and columns chosen last are remembered per list for the next detail; search and filters are not. **Show in Albums** (Tracks, Films, Subscriptions, Mixes) on that line opens the Browse page with the same scope, search, filters, order and view. A playlist's and a collection's own lists keep their playlist or collection order and controls, and their **Show in** link carries the search, the watched filter, the view and any order Browse also has; it is hidden while a playlist shows Metadata gaps, which Browse cannot filter by.
- BROWSE-09: Unloaded slots retain their exact row or card geometry with a subtle wipe skeleton, disabled under `prefers-reduced-motion`. Keep the rendered DOM bounded to the viewport and overscan. Scrolling stays within the fixed shell, with keyboard scrolling, responsive grid columns, column resizing and detail return position preserved.
- BROWSE-04: Table headings remain visible; rows are compact and columns independently selectable, resizable and saved per library. Columns are reordered in Filters > Columns by dragging a column's handle or with the Up and Down keys on it; the first column stays first and **Reset order** restores the default. The order is saved per library and carried in the URL (`columnOrder`). Horizontal scrolling must not widen the whole page. Long values truncate without losing access to their full content. The table is the one shared table: 28px header, 32px rows, the identity (title) column first and pinned while the rest scrolls sideways (on phones no column is pinned: the whole table scrolls sideways, and no column is wider than two thirds of the screen, so part of the next one always shows), numbers right-aligned, ISO dates and an en dash for a missing value. The identity cell carries a small thumbnail and, for tracks, the Play and Add to queue pair. Sorting uses the header buttons; a new sort starts descending for dates, counts and ratings and ascending for text, and choosing the active column again reverses it. The Columns picker and the sort list follow one field order (identity, creator, parent, properties, dates, counts, ratings, pills), with Description offered last. Shown columns keep the order they were chosen in; a newly chosen column goes before the trailing tag column, which absorbs spare width. Each rating is its own sortable column; there is no Providers column. Default columns: Albums: Title, Artists, Released, Added, Tracks, Scrobbles, RYM, Tags. Films: Title, Directors, Released, Runtime, Watched, Added, IMDb, Metacritic, RT, Tags. Tracks: Title, Artists, Album, Duration, Added, Scrobbles, Playlists, Tags. Artists: Artist, Country, Added, Albums, Tracks, Tags. Subscriptions: Title, Channel, Published, Duration.
- BROWSE-05: Grid cards use square album, track and mix art, portrait film posters, round artist and person art, or 16:9 subscription thumbnails. Tracks use their own artwork or artwork from the linked album. Artwork is clean: nothing sits on it except the play group (Play, Add to queue and More where music can be played, More alone on films, subscription items and mixes; on hover and focus, and always on touch), provider shortcuts when filtered, and one small badge, such as Needs ID or a video length. Under the artwork a card shows the title (opens the item), the creator, one meta line and one tags line. The meta line has the year or a count on the left and one value on the right: the headline rating (RYM for albums, IMDb for films) as a neutral source label and score, or the value of the active sort. Sorting by a rating marks that rating. Ratings on scales up to 10 always show one decimal (`8.0`); larger scales show whole numbers. In Albums and Films, Filters > View > On cards turns the rating, the sorted value and the tags line on or off; all three are on by default and stored in the `overlays` URL parameter. Missing or failed art shows the neutral placeholder for the kind of item, not the title. Rating marks are neutral: scores use text in cards, rows and table cells.
- BROWSE-05a: In Albums, Tracks, Films and Artists, an included or required Provider filter adds a shortcut to each result with a known item page on that provider. Put the provider mark immediately after the play group, or in the same action position on a result without one. Each shortcut opens its item in a new tab and stays usable when playback is disabled. Excluded providers add no shortcut. Clearing the filter removes its shortcut in Grid, List and Table.
- BROWSE-06: Selecting an item opens an accessible detail panel: a drawer over the results from the right, or a bottom sheet on phones. Artwork and titles open the item; only Play and Add to queue play, and double-clicking a row or card does nothing. While it is open, Up/Down in the results moves the selection. The sorted field is pinned first among the detail metrics. Close, Escape and browser Back preserve query, loaded rows and scroll. A direct detail URL remains usable. Keyboard focus returns to the trigger.
- BROWSE-07: Persist view, columns, sorting and filters independently for each library. URL state takes precedence over stored defaults. On phones the search takes the first toolbar row and the other controls the second. The grid starts compact on phones and shows three columns (two at standard density), the play pair is always visible, and the list drops tags and trailing values.
- BROWSE-08: Loading, errors, empty results and completed pagination are explicit. Loading shows skeletons the size of the content, and the count shows a skeleton while counting; no "Loading..." text or blank infinite spinner. A load error is a notice above the results, "Could not load albums", with a small Retry button; loaded rows stay. An empty library says "No albums yet", with Add album where the library has one; a search or filter with no results says "No albums match" with Clear filters. Show the filtered total, not just the loaded count. While a search, filter or range is active the count reads `N of M albums`, M being the library's total. Counts name the thing and use the singular for one: `1 album`, `128 albums`.
- BROWSE-10: Every grid has a density: compact, standard or roomy. Grid size is the first control under View in the Filters drawer, offered while the Grid view is active, in every Browse page and in every grid inside a detail; it takes no room on the toolbar. Browse saves it independently per library and carries it in the URL (`density`); grids inside details keep one density per artwork shape (square, poster, video), carried in the detail URL where the detail keeps its view there. With nothing named or saved, phones (700px wide or less) start compact and wider screens standard; the phone default never causes a hydration mismatch or a visible change of card size. Compact never shows fewer than three columns, so a grid in a detail tab on a phone, which is narrower than the page, still shows three. A compact card shows its artwork, title, creator and one value (the year, the date or the album count), without the tags line or a second value, and row heights are reserved to match. Compact cards keep touch-accessible details and outbound links. Changing density recomputes virtual row geometry without unbounded loading, overlap or horizontal page overflow. Titles carry no provider icon; the Spotify link sits at the end of the detail header.

- BROWSE-11: One Library selector (Albums, Tracks, Artists, Films, Subscriptions, Mixes) chooses the library pages shown in the navigation rail. Albums has Browse, Playlists, Collections, Tags and Imports; Films has Browse, People, Collections, Tags and Imports; Tracks has Browse, Playlists and Imports; Artists has Browse; Subscriptions has Browse, Channels and Imports; Mixes has Browse, Shows and Imports. Jobs and Providers appear once, under System, for every library, and filter by library on their own pages (All libraries by default; old links with `mediaType` open that filter). On Jobs and Providers the rail keeps the library that was open before them, and choosing a library there opens its Browse page. Switching libraries keeps the section where applicable, including the same Last.fm/Spotify playlist source across Albums and Tracks, without stale previews, selections or item links. The Jobs item carries the activity count; its popover lists running work with progress, queued work with the provider wait that holds it, and counts that link to the filtered Jobs page. The Providers item counts providers that need sign-in, a key or have stopped. See [workspace navigation](../import-navigation.md).
- BROWSE-12: Subscriptions (`/subscriptions`) browses YouTube videos and podcast episodes together, following BROWSE-02, 03, 04, 06, 08 and 09. The table uses the shared table with a pinned title (not pinned on phones), the list uses 48px rows with video thumbnails, and grid cards show the length as a badge on the thumbnail and the type or view count in the meta line. An empty library says "No subscriptions yet" and links to Imports. See [Subscriptions](../subscriptions.md#browse-page).
- BROWSE-14: Mixes (`/mixes`) browses the stored archives of radio stations, following BROWSE-02, 03, 04, 06, 08 and 09 with the same controls as Subscriptions. Cards and rows use square artwork with the length as a badge; the table adds Show, Station and Artist. A mix is a link: details offer the station page and, where the station gives one, the recording, and nothing is played in the app. A billed artist that matches a library artist opens that artist; an artist with such mixes lists them in a Mixes tab. An empty library says "No mixes yet" and links to Imports. See [Mixes](../mixes.md).
- BROWSE-13: List rows are 48px with a 40px thumbnail, the title over the creator, the play group (Play, Add to queue and More where music can be played, More alone on films, subscription items and mixes), a tags column and right-hand values under labelled list columns. On phones the list drops tags and values.

- BROWSE-15: The workspace tab bar stays visible above each signed-in page and its inspector. Option-click on Mac or Alt-click on Windows and Linux opens an internal destination in a background workspace tab. This includes tag and collection pills, metadata badges, filter suggestions, and counts on detail sections. A stored entity opens its own page. A filter opens its results with the current Browse settings and scope. Clicking passive metadata on a card or row with the modifier opens the item. The source view keeps its filters, selection, and inspector. The same modifier with Enter opens the focused destination. The + button duplicates the current tab and selects the copy, preserving its address, applied Browse settings, inspector trail and scroll positions. Each tab has its own ×. Closing the last tab opens Films. Reloading in the same browser tab restores the signed-in workspace.

## Acceptance

Jump directly from the first page to near the end in grid and table: verify only nearby pages are requested, the scrollbar height is unchanged, and the last partial row has no invented items. Scroll rapidly and change filters while requests are pending; stale results must never enter the new view. Verify bounded DOM/cache, zero results, retry after an error, reduced motion, and opening/closing an item without losing position. Test 390px and desktop widths, keyboard-only navigation, column resize, rating links and failed artwork.
