# Browsing and navigation

## Requirements

- BROWSE-01: Albums, Tracks, Artists, Films and Subscriptions each support a table, compact list and image-first grid. Albums, Films and Subscriptions start in Grid. Tracks and Artists start in List. Text is high contrast and dividers are subtle. Album tags use scrollable badge strips in every view. Artists uses the Tracks Browse controls and behavior, including full autocomplete and AI search, field filter modes, ranges, sorting and independent count/page loading.
- BROWSE-02: Keep library navigation, universal search, sorting, sort direction, view toggle and result count close together. One Filters button opens a drawer from the right with collapsible Views, Smart playlists (albums), Ranges, Listening (albums) and Columns (table) sections. Active filter chips stay in the navigation rail or mobile filter row.
- BROWSE-03: Every paginated grid, table, list and detail section reserves a viewport of placeholders while its initial total is unknown, then reserves the full matching result height. Scrollbar jumps request only the viewport and nearby pages. Keep count and visible page queries mounted, retain visited pages under the shared cache policy, and cancel obsolete reads. Reset on query changes, including same-count results. Use stable ordering with an ID tie-breaker. Failed pages keep their reserved space and offer Retry. When rows and count have separate endpoints, ready rows remain usable while counting or after a count failure.
- BROWSE-03a: Collection and item directories must be paginated at the API, even if an older endpoint returned an array. Apply search and sort over the full matching dataset before limiting each response. Exact counts travel separately when they would delay usable rows. Enrich only the returned page; a visible page must not trigger whole-directory payload expansion. Regression checks must assert bounded response size and requested pages as well as bounded DOM.
- BROWSE-03b: Nested media lists offer Grid, List and Table using the same dataset, filters, sorting and bounded page cache. Primary and embedded views use the shared Browse toolbar, sort controls and view switcher. Remember the choice independently for each nested list type. Changing presentation must not fetch the remaining dataset or change what Play and Add to queue refer to. Placeholder geometry and full scroll extent must match the chosen presentation.
- BROWSE-09: Unloaded slots retain their exact row or card geometry with a subtle wipe skeleton, disabled under `prefers-reduced-motion`. Keep the rendered DOM bounded to the viewport and overscan. Scrolling stays within the fixed shell, with keyboard scrolling, responsive grid columns, column resizing and detail return position preserved.
- BROWSE-04: Table headings remain visible; rows are compact and columns independently selectable, resizable and saved per library. Horizontal scrolling must not widen the whole page. Long values truncate without losing access to their full content.
- BROWSE-05: Grid cards use square album and track art, portrait film posters or 16:9 subscription thumbnails. Tracks use their own artwork or artwork from the linked album. Album and film cards show title, artist or director, and concise release or sort information. Ratings and provider icons share a strip. In Albums and Films, Filters > Views > On artwork controls where the strip, active sort value and tag badges sit. Sorting by a card rating highlights that rating. Missing or failed art has a visible fallback. External destinations use explicit links while titles open details.
- BROWSE-06: Selecting an item opens an accessible detail panel: a drawer over the results from the right, or a bottom sheet on phones. While it is open, Up/Down in the results moves the selection. The sorted field is pinned first among the detail metrics. Close, Escape and browser Back preserve query, loaded rows and scroll. A direct detail URL remains usable. Keyboard focus returns to the trigger.
- BROWSE-07: Persist view, columns, sorting and filters independently for each library. URL state takes precedence over stored defaults. Mobile controls stay within two rows, cards shrink to at least two columns (three at standard density where available), and touch actions remain accessible.
- BROWSE-08: Loading, errors, empty results and completed pagination are explicit. No blank infinite spinner. Show filtered total, not just currently loaded count.
- BROWSE-10: Album and film grid density is configurable and saved independently per library. Compact mobile cards prioritize artwork and legible title and creator information, with touch-accessible details and outbound links. Changing density recomputes virtual row geometry without unbounded loading, overlap or horizontal page overflow. Use a single small Spotify icon alongside an album title when it has a Spotify destination.

- BROWSE-11: One Library selector (Albums, Tracks, Artists, Films, Subscriptions) scopes the available sections. Tracks has Browse, Playlists and Imports, without album-only Tags or metadata sections. Subscriptions has Browse, Channels, Imports, Jobs and Providers and no Tags. Switching libraries keeps the section where applicable, including the same Last.fm/Spotify playlist source across Albums and Tracks, without stale previews, selections or item links. Shared account/job links identify their destination. The activity control shows every library and links to the correct scoped jobs or imports. See [workspace navigation](../import-navigation.md).
- BROWSE-12: Subscriptions (`/subscriptions`) browses YouTube videos and podcast episodes together, following BROWSE-02, 03, 04, 06, 08 and 09. The table uses the shared compact table, the list uses thumbnail rows, and grid cards show the type and length over their thumbnails. An empty library links to Imports. See [Subscriptions](../subscriptions.md#browse-page).

## Acceptance

Jump directly from the first page to near the end in grid and table: verify only nearby pages are requested, the scrollbar height is unchanged, and the last partial row has no invented items. Scroll rapidly and change filters while requests are pending; stale results must never enter the new view. Verify bounded DOM/cache, zero results, retry after an error, reduced motion, and opening/closing an item without losing position. Test 390px and desktop widths, keyboard-only navigation, column resize, rating links and failed artwork.
