# Search, filters and sorting

## Requirements

- SEARCH-01: One substring autocomplete retains the input after selection and finds titles, artists/directors/cast/writers, genres/tags, countries, languages, production companies, sources, watched state, collections, playlists and providers. Suggestions have field labels and whole-library counts; they must not be limited to the first loaded page. Free-text search splits the text into words; every word must appear, case-insensitively and as part of a value, in at least one text field, and words may match different fields. Scope suggestions to the active library and search text; cancel superseded requests rather than showing stale matches. Filters and titles share one ranked list: exact match, then the value starts with the text, then every word starts a word of the value, then substring only. Within a level, filters precede titles and filters covering more items come first; after three suggestions of one kind, the best of the other kind follows if it matches at least at word-start level.
- SEARCH-02: Metadata clicks add the exact corresponding filter. Each chip can be removed and explicitly changed between Any (OR), Required (AND), and Exclude (NOT). Preserve old semantics, including cross-field OR. Labels, not colour alone, identify modes. Prevent duplicate chips.
- SEARCH-03: Numeric and date ranges are available in both table and grid. Bounds are inclusive; missing values have a separate checkbox. Clear each range or all filters. No conversion of missing values to false zeroes except the documented scrobble default.
- SEARCH-04: Every supported numeric metric and sortable text column appears in sorting. Ascending/descending is explicit. Missing values go last in both directions; ties resolve by canonical ID. Grid displays the selected metric when it is not already visible.
- SEARCH-05: Persist text, numeric filters, sort and direction; preserve them through details, back navigation and reload. URL parameters are validated. Autocomplete supports arrows, Enter, Escape, clear and accessible names. Enter applies the typed text as a free-text search; it selects a suggestion only after the arrow keys have highlighted one.
- SEARCH-06: Numeric metrics supplied by local plugins use the same controls without hardcoded provider names in public code.
- SEARCH-07: Album listening controls accept up to ten count rules over all stored history, rolling day/week/month/year periods or inclusive UTC date ranges. Match all or any rules, combined with other browse filters; allow zero and independently chosen count bounds. Sort by scrobbles in a configurable period, show that count in grid/table, and preserve rules and sort period through URL state, reload and details. Count only linked stored scrobbles, without substituting provider totals or starting a sync. Explain that counts are track plays and depend on synced history.
- SEARCH-08: Subscriptions use the same autocomplete, chips, ranges and AI search as the other libraries, over title, channel or podcast, type (`YouTube` or `Podcast`) and tags, with Published, Duration, Views, Likes and Comments ranges. Text applies on Enter or when an option is chosen. Sorting offers relevance while searching, then published date, title, channel, duration, views, likes and comments.

## Acceptance

Verify filter combinations on synthetic fixtures: two includes in different fields, required/excluded tags, empty filter set, scalar/array fields, range endpoints, missing numbers and free-text words that match different fields. Test suggestions for source, title and creator, including a value outside the first page. Check every metric from the music and film requirements is selectable.
