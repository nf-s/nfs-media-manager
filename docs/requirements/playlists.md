# Library playlists and smart playlists

A playlist is a named, ordered list of items from one library, made in the app. A smart playlist is a named Browse view of one library: it lists what matches each time it is opened. Both live under **Playlists** in Albums, Tracks, Films, Subscriptions and Mixes. Artists have neither. Nothing here is sent to Spotify; imported Spotify playlists stay as they are ([tracks and Spotify playlists](../tracks-and-playlists.md)) and are never a target of **Add to playlist**.

Out of scope: a limit set in the interface on a smart playlist, adding an album's tracks to a track playlist, freezing a smart playlist into a playlist, mixing libraries in one playlist, and syncing to a provider.

## Storage

- PL-01: `library_playlist` holds both kinds: `id`, `library` (`albums`, `tracks`, `films`, `subscriptions`, `mixes`), `type` (`playlist`, `smart`), `name`, `view` (the saved view, required for `smart` and null otherwise), `legacy_key` (unique, set only on a smart playlist made from a legacy saved view), who created it, `deleted_at`, and created and updated times. `updated_at` moves when the name, the view or the entries change. A name is 1–200 characters after trimming and unique within its library without regard to case among playlists that are not deleted; in Albums and Tracks it must also differ from every listed imported playlist's name.
- PL-02: `library_playlist_entry` holds the entries of a playlist: `id`, `playlist_id` (cascade), `position`, exactly one of `media_item_id` and `subscription_item_id` (both cascade), `added_at`, `batch_id` (the addition that created it) and `removed_batch_id` (set while a removal can still be undone; such an entry is not listed, counted or matched). The same item can be in a playlist more than once. An entry's item must belong to the playlist's library: the media type for Albums, Tracks and Films, and the subscription type's library for Subscriptions and Mixes. An item can be added to a playlist only if that library's Browse at the In library scope can list it. Indexes serve entries by playlist and position and playlists by item.
- PL-03: Deleting a playlist sets `deleted_at`; restoring clears it. A later write removes playlists deleted more than 24 hours ago, except those with a `legacy_key`, which stay as a record that the owner deleted them, and entries removed more than 24 hours ago.
- PL-04: A saved view is the set of Browse URL parameters that decide the result and its order: the search, field choice, filters, ranges, tag location, listening conditions and sort, library scope and discovery sources, archived and edition switches, grouping, a result limit, sort field and direction, and a creator or source scope when one is set. View layout, density, columns and card overlays are not part of it. It is stored as a map of parameter names to their URL values and validated on every write against that library's Browse query schema; an invalid view is a 422.
- PL-05: Legacy saved views (MUSIC-05) become Albums smart playlists. When Albums smart playlists are first read, each view in the newest stored legacy import that has no `library_playlist` row with its `legacy_key` is inserted with its name, filters, ranges, tag location, listening conditions, sort and limit; a name that is taken gets a numbered suffix. The insert is idempotent and a deleted one is not inserted again. `GET /api/v1/imports/saved-views` and the Albums **Smart playlists** select that read it are removed: the Filters drawer reads smart playlists (PL-42).

## API

All routes are under `/api/v1/library-playlists`, require the session, validate with shared schemas in `packages/schemas/src/library-playlists.ts`, and keep handlers thin. Every list is a bounded page (at most 100 rows) searched and sorted on the server.

- PL-10: `GET /` lists one library's playlists for pickers: `library`, optional `type`, `q`, `page`, `size` (default 25), and optional `itemId`, which adds whether each playlist already holds that item. A row has `id`, `library`, `type`, `name`, `entryCount` for a playlist, `view` for a smart playlist and `updatedAt`.
- PL-11: `POST /` creates a playlist (`library`, `name`, optional selection to add) or a smart playlist (`library`, `name`, `view`). `PATCH /:id` renames or replaces the view. `DELETE /:id` deletes and `POST /:id/restore` restores. A taken name is a 409 with the message "A playlist with this name exists."
- PL-12: `GET /:id` returns the playlist with its entry count and how many entries repeat an item already earlier in it. `GET /:id/entries` returns a page of entries in position order, each with its entry `id`, position, added date and the item's Browse summary for that library (enough for the title, artwork, creator or channel, and the play controls).
- PL-13: A selection is either `{ ids }` (at most 10,000) or `{ query, excludeIds }`, where `query` is that library's Browse query and the server resolves every match from the filters itself, independently of what a client has loaded, in the Browse order, less `excludeIds`. A selection that resolves to more than 10,000 items is a 422 that says so. Resolving and adding use a bounded number of statements whatever the selection size.
- PL-14: `POST /:id/entries/check` takes a selection and returns how many items it holds, how many are already in the playlist and the title and creator of the first five of those. `POST /:id/entries` takes a selection and `duplicates` (`skip` or `again`), appends in selection order and returns `added`, `skipped`, `repeated` (added although present) and the `batchId`. `DELETE /:id/entries/batches/:batchId` removes what that addition added.
- PL-15: `POST /:id/entries/remove` takes entry IDs (at most 100) or `repeats: true` (every entry whose item is already earlier in the playlist) and returns `removed` and a `batchId`; `POST /:id/entries/restore` with that `batchId` puts them back in place.
- PL-16: `GET /memberships` (`library`, `itemId`) lists the playlists that hold an item, at most 100, with their entry counts.
- PL-17: The Playlists directory is one paged read with its count read separately: for Albums and Tracks it lists imported playlists and that library's playlists and smart playlists together; for Films, Subscriptions and Mixes that library's only. Search, sort (name, type, source, count, updated and the existing imported-playlist sorts) and paging apply to the combined result on the server.
- PL-18: Browse in every one of the five libraries accepts a filter on a library playlist by ID (`field: libraryPlaylist`) with the Any, Required and Exclude modes, as a chip and in the URL. It matches items with a listed entry in that playlist. It has a workload and budget in the performance suite for Tracks (Title and Added pages), Albums, Films and Subscriptions, and does not add a statement to a Browse read.

## Add to playlist

- PL-20: In Table view the selection bar offers **Add to playlist** beside **Merge**; in a library without Merge it is the bar's primary button. It opens a picker headed "Add 40 tracks to a playlist" (or "Add “Title” to a playlist" for one item) with a **Find a playlist** search field, **New playlist…** first, then that library's playlists with their counts. Imported playlists and smart playlists are not listed. For one item, a playlist that already holds it shows a tick and "Already added".
- PL-21: **New playlist…** asks for a name (the picker's search text, or for a selection the current view's suggested name) with **Back** and **Create and add 40** (**Create and add** for one item). A taken name shows "A playlist with this name exists." and disables the button.
- PL-22: Choosing a playlist that holds none of the selection adds it at once. Otherwise the picker shows the playlist's name as its heading, then "6 of 40 tracks are already in this playlist." with the first five as "Title · Artist" and "+1 more", and **Cancel**, **Add again** and **Skip duplicates** (primary). When every selected item is present it reads "All 40 tracks are already in this playlist." and offers **Cancel** and **Add again**. For one item it reads "“Title” is already in this playlist." with **Cancel** and **Add again**.
- PL-23: The result line replaces the selection bar and clears the selection: "Added 34 tracks to “Late shift”. Skipped 6 already there.", "Added 40 tracks to “Late shift”. 6 were already there and are now in it twice.", "Added “Title” to “Late shift”." (" It is now in it twice." after Add again), "Created “Name” with 40 tracks.", with **Open playlist**, **Undo** and **Dismiss**. Undo shows "Undone: " and the same text. With the Filters drawer or a detail open, the line is drawn at the foot of that panel. The text is cut with an ellipsis on one line at every width and the buttons stay in place.
- PL-24: A three-dot **More actions** button follows Play and Add to queue wherever the pair appears for an album or track: Browse table rows, list rows and grid cards, detail track lists, playlist rows, similar items and the player's current track. Films, subscription items and mixes, which the app cannot play, get the button alone in the same position. On a card whose artwork carries a badge, such as a duration or “Needs ID”, the button sits above the badge in the same corner; it never covers it. Its menu has **Add to playlist…** and **Open details**; inside a playlist it has **Add to another playlist…** (the picker leaves that playlist out) and, for a library playlist, **Remove from this playlist**. The group stays visible while its menu is open. Provider marks follow the group.
- PL-25: An item's details have **Add to playlist** in the header and **Add to playlist…** under More, and a **Playlists** section that lists the library playlists holding it with "Library · 18 tracks", or "In no playlist". Where details already list imported playlists, library playlists join that list. The existing action that adds an album or track to a Spotify playlist is labelled **Add to Spotify playlist**.
- PL-26: On phones a menu or picker opened from a row is a sheet at the bottom of the screen over a scrim, with touch-height items.

## Select all matching

- PL-30: In Table view the Browse toolbar shows **Select all matching** after the count, with the title "Select all 128 tracks that match, including rows not loaded yet". It selects the whole result of the active search and filters on the server (PL-13); rows are shown ticked as they load, and unticking one excludes it. Once every loaded row is ticked and more match, the bar also offers **Select all 128 matching** (hidden on phones, where the toolbar link remains). The bar reads "128 selected of 128".
- PL-31: The header checkbox is labelled "Select loaded tracks" and, while the whole result is selected, "Select all matching tracks". Changing the search, a filter or the sort clears the selection.
- PL-32: **Add to playlist** accepts a whole-result selection. It adds the rows of the view's query that are in the library, so at the Outside scope a whole-result selection adds nothing: the server refuses it with the PL-02 message and the button is disabled with the title "Items outside the library cannot be added to a playlist." **Merge** needs ticked rows: while the whole result is selected it is disabled and its title says so. Artists Browse, which has only Merge, does not offer Select all matching.
- PL-33: Films, Subscriptions and Mixes have the checkbox column, the header checkbox and the selection bar in Table view. Grid and List have no checkboxes in any library.

## Smart playlists

- PL-40: When the view has a search or at least one filter, range or listening condition, the rail shows **Save as smart playlist** under the active filter chips (the phone filter row shows the same button), and Filters → **Smart playlists** shows **Save current view**, disabled with the title "Search or add a filter first" otherwise. Both open a popover headed "Save smart playlist" with **Name** (suggested from the tag values and the search), the view written out, "Lists what matches each time it is opened.", **Cancel** and **Save**. The result line reads "Saved smart playlist “Name”." with **Playlists** and **Undo**.
- PL-41: A view is written out as its filters, then its order, joined with " · ": "Tag: Ambient or Jazz · Search: “rain” · In playlist: Late shift · Added, newest first"; with no filter it starts "All tracks". Values of one field in Any mode are joined with "or", Required with "and", and Exclude reads "Not". Direction words: newest or oldest first for dates, A to Z or Z to A for text, longest or shortest first for durations, highest or lowest first otherwise. One function writes it for the popover, the drawer and the Playlists table.
- PL-42: Filters → **Smart playlists** has a **Saved view** select ("Choose a saved view") listing that library's smart playlists and the current view written out beneath it. Choosing one opens it.
- PL-43: Opening a smart playlist opens Browse with its view and its ID in the URL. The rail then shows **Smart playlist**, its name, the chips and **Close**, which clears the view and the ID. When the view differs from the saved one the name is followed by "Changed" and the rail offers **Update** (primary) and **Save as new**; the drawer offers **Update “Name”** and **Save as new**. Update reports "Updated “Name”." with **Playlists** and **Undo**.
- PL-44: In every library with playlists, the Browse search box also suggests that library's playlists and smart playlists whose label matches the typed words, ranked with the other suggestions by name. A playlist reads **Playlist: Name** with its entry count; choosing it adds the playlist filter, chip "Playlist: Name", as other values are added. A smart playlist reads **Smart playlist: Name** with "Open"; choosing it opens it as the Saved view select does (PL-42, PL-43), replacing the search, filters, ranges and sort. Typing "playlist" or "smart playlist" before a name narrows to them, as a field name does for other values. Imported playlists keep their own **Playlists: Name** suggestions.

## Playlists

- PL-50: **Playlists** is a navigation item in Albums, Tracks, Films, Subscriptions and Mixes. The page has **New playlist** in its head, a **Search playlists** field, the count ("5 playlists") and one table whose default columns are **Playlist** (name, with Play and Add to queue in Albums and Tracks), **Type** (Playlist or Smart playlist), **Source** (Library, Spotify, Liked Songs), the item count headed with the library's noun, **Saved view** (written out, cut with an ellipsis, an en dash for a playlist), **Updated** and a three-dot menu. The imported-playlist columns that exist today remain available under Columns. A smart playlist's count is the number that matches now, read per visible row through the Browse count.
- PL-51: The three-dot menu, on library rows only: **Open in Browse** (smart), **Rename**, and **Delete playlist** or **Delete smart playlist**. Rename opens the name popover headed "Rename" with **Rename**; **New playlist** opens it headed "New playlist" with **Create** and reports "Created “Name”.". Delete reports "Deleted “Name”." with **Undo**; a Browse filter on a deleted playlist reads “Playlist: removed” and matches nothing until the chip is removed or the delete is undone.
- PL-52: A smart playlist's name opens Browse with its view. A playlist's name opens it in the inspector: the kind **Playlist**, the name, "52 tracks · Updated 2026-11-28 · Library", Play and Add to queue under the artwork in Albums and Tracks (they play the entries in order), **Filter tracks** (Browse filtered by the playlist, as a chip "Playlist: Name"), More with **Rename** and **Delete playlist**, and a section headed with the library's noun: a table of position, title with the play group, creator or channel, and **Added to playlist**. An empty one reads "Empty playlist" and "Add tracks from Browse."
- PL-53: When a playlist holds an item more than once, its detail shows "3 tracks are in this playlist more than once." with **Remove repeats**, which keeps the first of each and reports "Removed 3 repeats from “Name”." with **Undo**. **Remove from this playlist** reports "Removed “Title” from “Name”." with **Undo**.

## Design system

- PL-60: The play control becomes a group of three: Play, Add to queue, More actions. The change is made in `components.css`, the React component, the Play section and its rules on the components page, `assets/ds.js` and every sentence in the docs that states the pair rule. The phone sheet for row menus (PL-26) and the result line's one-line rule (PL-23) are stated on the components page.
