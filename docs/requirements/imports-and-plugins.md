# Imports, providers and safety

## Requirements

- IMPORT-01: Read current raw and cleaned local JSON, never checked-in build output. Keep original files unchanged. Import is repeatable, preserves canonical IDs, merges rather than deletes history, and reports skipped/invalid records. Provide a tiny-fixture test before full local import.
- IMPORT-02: Cleaned browse values, including derived ratings but excluding retired Spotify audio features, are imported explicitly. Raw snapshots alone are not parity. Preserve ancillary artist, playlist, blacklist/missing and file-provenance data. Reconcile counts and fields after import and verify a second run adds no duplicate entities or identical snapshots.
- IMPORT-03: File-based ingestion (NFO, CSV ratings/watchlist, album/UPC lists, legacy libraries) belongs under Imports, not executable scraping providers. UI describes supported inputs truthfully and shows success/failure counts. Never offer a nonfunctional provider action.
- IMPORT-04: CSV ingestion offers type selection and drag/drop, validates and previews before canonical writes, then imports the explicitly selected rows. NFO traversal uses a server-configured directory, previews only new films, and never offers a browser-editable path. Reviewed selections are owner-bound, expiring and single-use.
- IMPORT-05: Preserve shared IMDb/TMDb identifiers from every CSV/plugin format. Missing IDs do not discard titled films: assign an internal ID, show Needs ID in preview/browse/detail, and provide provider-specific editable ID rows. Corrected shared film IDs feed other scrapers and survive future payloads.
- IMPORT-06: After confirmation, queue selected configured providers **only for films newly created by that import**, never existing films (even when they lack provider metadata). CSV previews distinguish new, changed and unchanged films, with specific field changes and before/after values. Identical rows do not rewrite canonical timestamps, provider state or snapshots; legitimate personal ratings, watchlist/bookmark state, dates and identifiers still import. Recheck identity and changes transactionally at execution; final counts describe actual outcomes, not stale preview estimates. A row that becomes existing after preview is never enriched; a deleted existing row requires another preview before creation. Broad-run confirmation, in a popover on the import button when more than five metadata jobs would be queued, counts only selected new films times selected providers. Skip previously scraped/queued work and clearly report missing identifiers/credentials. A header indicator links to activity/errors. Jobs include names/types, infinite scrolling, filtering and explicit retry of unsuccessful work only. Jobs and CSV/NFO previews fill the remaining viewport with independently scrolling lists rather than scrolling the whole page. Preview selections persist as more rows appear; scrolling never imports or queues work. Job polling and filter changes retain their existing behavior.
- IMPORT-07: Jobs support individual checkboxes, inclusive Shift-click range selection in displayed order, a select-all-loaded checkbox with mixed state, and clear selection. There is no total selection limit; actions are submitted in bounded serial HTTP requests. Filter changes clear selection; polling and infinite scrolling preserve selections by job ID. Failed/cancelled jobs can be retried if unfinished with no existing retry, or dismissed from attention without deleting history. Successfully queuing a replacement automatically dismisses the failed original in the same transaction; its error history remains available. A blocked retry leaves the original undismissed, and a failed replacement requires attention. Bulk retries require explicit confirmation above five unfinished items across the selection, retain provider safeguards, and show per-job skipped/blocked results. Successful work is not repeated and selecting rows never queues work. Row Retry and Cancel select that job and open the same review; a batch row's Retry opens the batch retry review, and its Cancel reviews cancelling every unfinished job in the batch, loaded or not (`POST /api/v1/scrape/jobs/batches/:id/cancel`; running jobs need the confirmation the review asks for, and finished jobs keep their results).
- REFRESH-01: One metadata workspace handles first scrapes and refreshes for the selected film or album library. Show Title, album Artists and Added by default, with configurable browse columns and a status/last-successful-scrape column for each eligible provider. Show a Legacy import column with Yes/No values from the stored legacy-library marker or retained legacy import snapshots and an All/Yes/No filter in both libraries. Apply this filter before pagination and combine it with the other metadata filters. Show the latest started attempt as a status (Failed with its stored error, Running, Cancelled) linking to the job, followed by the age of the last successful scrape when one exists. A successful scrape shows its age in words; one older than 180 days uses the attention colour. No attempt and no success shows Never; an artist attempted without success shows Not scraped. Missing identifiers show a Needs ID pill. Preserve the last successful scrape date when a later attempt fails. Queued jobs and jobs cancelled before starting do not count as attempts or replace an earlier outcome. Support sorting, text/facet/range search and independent provider filters: Never attempted (no started attempt or successful scrape), Failed (latest started attempt failed), No successful scrape (including failures), and no success or older-than thresholds. Multiple provider filters intersect. Successful scrape timestamps alone determine freshness; imports/edits never reset it. Recheck the same predicates before queueing. Browsing the table never makes provider requests.
- REFRESH-02: Select media explicitly with checkboxes, inclusive Shift ranges and select-all-loaded with mixed state. Nothing is selected initially. Filter/sort changes clear row selection; changing the target provider selection clears broad-run confirmation. The selection bar appears under the table once rows are selected; it chooses the providers to fetch, shows the resulting operation count and launches only on explicit action. There is no total row-selection cap: dispatch serial transport chunks of at most 100 explicit IDs, reusing one-item/provider enrichment jobs and provider safeguards. Require confirmation above five item/provider operations. Missing identifiers remain visible and marked; invalid/active work is skipped at scheduling and provider freshness constraints are rechecked. An uncertain request failure stops further chunks, retains unconfirmed selections and links to batch progress instead of automatically retrying.
- REFRESH-02a: Artist metadata offers **Select all matching**, in the toolbar after the count, independently of loaded pages. Save an owner-bound, expiring snapshot of the filtered IDs, including the result cap; selecting it must not hydrate every row or queue jobs. Allow individual exclusions, clear the selection when filters or sorting change, and read IDs in batches of at most 100 for explicit dispatch. Preserve confirmed progress after an uncertain batch and skip missing or archived artists. The header checkbox states whether it controls loaded rows or the saved matching selection.
- REFRESH-03: Album, film and artist details group provider identifiers, refreshes and evidence in Sources. Refresh one provider from its row or every eligible provider with **Refresh all**, by explicit action, with one job per provider for the open item. A provider's history lists its stored snapshots and jobs. Read the stored response and normalized data only when opening a snapshot. Album and film Edit remains for manual item fields and those edits. Track and subscription sources describe their existing provenance and use their own import or sync workflows.
- SCROBBLE-01: The scrobble link report shares table primitives and selection behavior with album metadata. Sort the whole filtered result before paging, clear selection on filter/sort changes, and preserve it while loading more rows. Explicit bulk Spotify searches create one task job per unlinked artist/album group, with serial transport chunks of at most 100 and confirmation above five operations. Persist candidates against the source group, retain normal job cancel/retry/history and Spotify safety controls, and never add library albums automatically.
- SCROBBLE-02: Add new album prefills and starts the Spotify search on explicit opening, reusing saved candidates when present. The library picker prefills the album title and searches only in its active tab. Adding closes the panel immediately with background progress and recoverable errors. Sync schedules include 10 and 30 minutes, 1, 3 and 6 hours, daily, weekly and off; only completed syncs are scheduled again.
- PLUGIN-01: Private providers live in an ignored local package with its own manifest, implementation, tests and setup documentation. Public code loads configured package paths through the shared SDK. No provider name, URL, credentials or private fixture enters tracked source/docs.
- PLUGIN-02: The package declares identity/display name, supported kinds, credential definitions, rate limits, normalization and legacy import hook. Import needs no scraping credentials. Optional provider browse fields are declared via the SDK and displayed generically.
- PLUGIN-03: An absent plugin must not break public imports or browsing. Report skipped integration data; do not discard raw input files. Invalid plugins fail clearly. Restart/reload discovers installed plugins. Optional packages can be backed up independently.
- SAFETY-01: Tests, file previews, legacy imports and imports with no selected metadata providers make no live scraping calls. Confirmed album and film imports may queue the selected providers; the importer itself never calls their scraping methods. Never run legacy scraper entrypoints. Large runs require explicit confirmation. Credentials are encrypted server-side; browser receives only masked metadata.
- SAFETY-02: Preserve hard minimum policies from the current scripts: Spotify 1 concurrent / 1500ms; MusicBrainz 1 / 1000ms; Discogs 2 / 1050ms; Last.fm 5 / 200ms; TMDb 1 / 333ms; OMDb 5 / 200ms. Extensions must enforce their declared request policy. More conservative limits are allowed, faster ones are not.
- SAFETY-03: Rate limits cover every outbound request, including retries and credential tests. Respect Retry-After and log progress and errors without secrets. The shared gate may retry a bodyless metadata GET to a serial provider after HTTP 502, 503 or 504, up to three attempts with bounded backoff. Each scheduled retry appears in job history. File imports do not need API keys.
- ADMIN-01: Require authentication for data, overrides, history, jobs and credentials. Keep Jobs, Imports and Providers secondary to browsing. Show real capability/status and concise empty states, without repeated administrative slogans.
- ADMIN-02: Jobs (`/jobs`) has two tabs: Activity (monitoring) and Metadata (`/jobs/metadata`, one metadata-selection destination for Albums, Films or Artists, chosen with a Library filter). Old new-scrape and refresh URLs (`/jobs/new`, `/jobs/refresh`) resolve to Metadata and retain media scope. Activity opens with a summary (queued, running, waiting on a blocked provider, needing attention; each count filters the table) and one box per busy or blocked provider linking to its page. The library is a filter (`mediaType`, All by default). Batches of more than one job are one row with progress and counts that expands to its matching jobs; queued jobs and batches show their wait (`Until 14:20` or the provider's reason). Preserve monitoring filters, polling, infinite scrolling, bulk actions, `jobId` and `batchId` deep links. Each job row offers the action that fits it (Retry or Cancel) through the same review as bulk actions. Opening destinations or editing forms never queues work; launched batches link to their progress.

- IMPORT-08: Album CSV and Spotify discovery use owner-bound, expiring, single-use previews with nothing selected initially. Album CSV requires title and artist; UPC format also requires a barcode preserved as text. Recheck identity at commit. Existing albums are unchanged and never enriched; queue only selected providers for newly created albums, confirmed in a popover on the import button when more than five metadata jobs would be queued. See [import workflows](../importing.md).
- IMPORT-09: Import and sync states use the shared status vocabulary: Queued, Running, Done, Failed, Cancelled, Paused, Never. Sync pages show their state with `Status`, progress with `Progress`, and their counts as Facts.
- IMPORT-10: Disconnect (Spotify on the album import, YouTube), Stop sync and Revoke API key always ask first, in a popover that says what stops working.
- ADMIN-03: Filter import history by declared library before limiting results, including pending and failed runs. Label unknown legacy scope in both libraries. Keep the running-import guard global. Job details identify the affected item and expose bounded, redacted failure diagnostics; historical batch repair must preserve IDs and history without scheduling work. See [job history repair](../job-history-split.md) and [worker recovery](../job-worker.md).
- ADMIN-04: Every queued job states why it waits (`waiting`: reason, `until`, detail), derived at read time from the provider's stored state once per response: access halt, dispatcher stop or pause (including job selection), missing plugin, offline local worker, cooldown, request budget, hourly or fixed-window limit, busy request slots, or nothing (`queued`). Task jobs report `progress` (`done`, `total`). Job detail leads with a `summary` (headline, stored error code, retry time, actions) derived only from the stored error and provider state; an unrecognised error shows its stored message with Retry. `GET /api/v1/providers/overview` returns every provider's connection, queue state, job counts, last success, 24 hourly request counts, budget, worker and concurrency in one bounded response for polling. It reports only whether credentials are set and accounts signed in, never their values; sign-in stays in its existing flows. Example: a synthetic provider cooling down after HTTP 429 shows queue `waiting`, reason `cooldown` and its end time.
- ADMIN-05: Providers (`/providers`) lists every provider once in one table, grouped into Accounts and Metadata, fed by `GET /api/v1/providers/overview` and refreshed every 30 seconds. A Library filter (All libraries, Albums, Films, Artists, Subscriptions) lives in the URL as `mediaType` and is passed to the endpoint; old `?mediaType=` links open the matching filter. Columns: provider (mark, name and purpose; opens the provider page), connection, queue state with its waiting reason and end time, queued, running and needs-attention counts (each linking to Jobs filtered to that provider and status), last success, requests over 24 hours, budget, runs on, and row actions. Row actions use the existing endpoints and keep their confirmations: Clear cooldown (`POST /api/v1/providers/:provider/cooldown/clear`, naming the cooldown end shown) and, where the cloud dispatcher is supported, Resume or Pause (`POST /api/v1/cloud/providers/:provider/dispatch`) behind a review. Providers whose queue is held or whose credentials or sign-in are missing are listed above the table as notices with an Open or Add key action. Providers shows connection state only: account sign-in stays in its import and player flows, and playback devices (Spotify, Sonos) connect from the player's Play on.
- ADMIN-06: Each provider has a page at `/providers/<providerId>` with the tab in the URL (`?tab=jobs`, `?tab=settings`; Overview has none). Links to a provider go straight to this page, with `?tab=settings` for sign-in or keys. The header shows the queue and connection state, the description and where it runs, with the queue controls (Resume or Restart, Resume all queued jobs, Pause queue, each reviewed first) and Open in Jobs. The waiting reason is a notice on every tab with the action that releases it (Clear cooldown, Resume, or Open settings). The header also has **Open site** (the provider's own site, from its manifest) and the More menu. Overview shows job figures, requests per day on the shared trend chart (30 or 90 days, the current day dotted; `GET /api/v1/providers/:provider/requests/daily`), Coverage (per library, how many of all its visible items have data from this provider, with a link to Metadata; `GET /api/v1/providers/:provider/coverage`; Metadata counts only the items the provider can look up, so its totals can be lower), recent error reviews and cooldown clears, the queue limits and budget, which credentials are set and the libraries it supplies. Jobs is the shared jobs table fixed to the provider. Settings holds credentials (never displayed; a blank field keeps its value), the request budget, request limits, lookup rules, integration details, the local worker and its transport switch, and reviewable error messages. Old `/providers?provider=<id>&section=<name>` links redirect to the provider page (`credentials` and `settings` open Settings, `jobs` opens Jobs, anything else Overview).

## Acceptance

CSV descriptive fields are bootstrap hints for new films. Existing-film imports only apply personal rating/watchlist/bookmark state and dates, plus missing identifiers. They do not replace canonical title/year/summary/artwork, library Added dates, source labels, public scores/vote counts, genres or credits; use an explicit metadata refresh for those. Preview and execution share this policy and preserve manual overrides. Equivalent personal state retained in legacy snapshots or source hints is recognized through a pure local-plugin hook, not reported as a new update merely because a newer canonical field is absent.

Test a fixture with a mock local plugin and missing plugin; validate canonical fields, snapshots and rate guards. Use a synthetic package to verify the exclusion from version control. Test import twice and compare database/source totals and values. Inspect browser network activity to confirm no scrape calls occur during browse/import testing.
