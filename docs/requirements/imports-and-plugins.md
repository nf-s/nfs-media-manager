# Imports, providers and safety

## Requirements

- IMPORT-01: Read current raw and cleaned local JSON, never checked-in build output. Keep original files unchanged. Import is repeatable, preserves canonical IDs, merges rather than deletes history, and reports skipped/invalid records. Provide a tiny-fixture test before full local import.
- IMPORT-02: Cleaned browse values, including derived ratings/audio metrics, are imported explicitly. Raw snapshots alone are not parity. Preserve ancillary artist, playlist, blacklist/missing and file-provenance data. Reconcile counts and fields after import and verify a second run adds no duplicate entities or identical snapshots.
- IMPORT-03: File-based ingestion (NFO, CSV ratings/watchlist, album/UPC lists, legacy libraries) belongs under Imports, not executable scraping providers. UI describes supported inputs truthfully and shows success/failure counts. Never offer a nonfunctional provider action.
- IMPORT-04: CSV ingestion offers type selection and drag/drop, validates and previews before canonical writes, then imports the explicitly selected rows. NFO traversal uses server-configured SCAN_DIR, previews only new films, and never offers a browser-editable path. Reviewed selections are owner-bound, expiring and single-use.
- IMPORT-05: Preserve shared IMDb/TMDb identifiers from every CSV/plugin format. Missing IDs do not discard titled films: assign an internal ID, show Needs ID in preview/browse/detail, and provide provider-specific editable ID rows. Corrected shared film IDs feed other scrapers and survive future payloads.
- IMPORT-06: After confirmation, queue selected configured providers **only for films newly created by that import**, never existing films (even when they lack provider metadata). CSV previews distinguish new, changed and unchanged films, with specific field changes and before/after values. Identical rows do not rewrite canonical timestamps, provider state or snapshots; legitimate personal ratings, watchlist/bookmark state, dates and identifiers still import. Recheck identity and changes transactionally at execution; final counts describe actual outcomes, not stale preview estimates. A row that becomes existing after preview is never enriched; a deleted existing row requires another preview before creation. Broad-run confirmation counts only selected new films times selected providers. Skip previously scraped/queued work and clearly report missing identifiers/credentials. A header indicator links to activity/errors. Jobs include names/types, infinite scrolling, filtering and explicit retry of unsuccessful work only. Jobs and CSV/NFO previews fill the remaining viewport with independently scrolling lists rather than scrolling the whole page. Preview selections persist as more rows appear; scrolling never imports or queues work. Job polling and filter changes retain their existing behavior.
- IMPORT-07: Jobs support individual checkboxes, inclusive Shift-click range selection in displayed order, a select-all-loaded checkbox with mixed state, and clear selection. There is no total selection limit; actions are submitted in bounded serial HTTP requests. Filter changes clear selection; polling and infinite scrolling preserve selections by job ID. Failed/cancelled jobs can be retried if unfinished with no existing retry, or dismissed from attention without deleting history. Bulk retries require explicit confirmation above five unfinished items across the selection, retain provider safeguards, and show per-job skipped/blocked results. Successful work is not repeated and selecting rows never queues work.
- REFRESH-01: One metadata workspace handles first scrapes and refreshes for the selected film or album library. Show Title, album Artists and Added by default, with configurable browse columns and a status/last-successful-scrape column for each eligible provider. Show the latest started attempt, including Failed with its stored error and a link to the job; preserve the last successful scrape date when a later attempt fails. Queued jobs and jobs cancelled before starting do not count as attempts or replace an earlier outcome. Support sorting, text/facet/range search and independent provider filters: Never attempted (no started attempt or successful scrape), Failed (latest started attempt failed), No successful scrape (including failures), and no success or older-than thresholds. Multiple provider filters intersect. Successful scrape timestamps alone determine freshness; imports/edits never reset it. Recheck the same predicates before queueing. Browsing the table never makes provider requests.
- REFRESH-02: Select media explicitly with checkboxes, inclusive Shift ranges and select-all-loaded with mixed state. Nothing is selected initially. Filter/sort changes clear row selection; changing the target provider selection clears broad-run confirmation. Bottom controls choose the providers to fetch, show the resulting operation count and launch only on explicit action. There is no total row-selection cap: dispatch serial transport chunks of at most 100 explicit IDs, reusing one-item/provider enrichment jobs and provider safeguards. Require confirmation above five item/provider operations. Missing identifiers remain visible and marked; invalid/active work is skipped at scheduling and provider freshness constraints are rechecked. An uncertain request failure stops further chunks, retains unconfirmed selections and links to batch progress instead of automatically retrying.
- PLUGIN-01: Private providers live in an ignored local package with its own manifest, implementation, tests and setup documentation. Public code loads configured package paths through the shared SDK. No provider name, URL, credentials or private fixture enters tracked source/docs.
- PLUGIN-02: The package declares identity/display name, supported kinds, credential definitions, rate limits, normalization and legacy import hook. Import needs no scraping credentials. Optional provider browse fields are declared via the SDK and displayed generically.
- PLUGIN-03: An absent plugin must not break public imports or browsing. Report skipped integration data; do not discard raw input files. Invalid plugins fail clearly. Restart/reload discovers installed plugins. Deployment docs explain how to keep the ignored package backed up separately.
- SAFETY-01: Tests, previews, legacy imports and imports with no selected metadata providers make no live scraping calls. Confirmed film imports may queue the selected providers; the importer itself never calls their scraping methods. Never run legacy scraper entrypoints. Large runs require explicit confirmation. Credentials are encrypted server-side; browser receives only masked metadata.
- SAFETY-02: Preserve hard minimum policies from the current scripts: Spotify 1 concurrent / 1500ms; MusicBrainz 1 / 1000ms; Discogs 2 / 1050ms; Last.fm 5 / 200ms; Google search 20 / 600ms; TMDb 1 / 333ms; OMDb 5 / 200ms. Private policy comes from the local package's old source. More conservative limits are allowed, faster ones are not.
- SAFETY-03: Rate limits cover actual outbound requests, including retries and credential tests, not just jobs. Respect retry-after, bound retries and log progress/errors without secrets. File imports do not need API keys.
- ADMIN-01: Require authentication for data, overrides, history, jobs and credentials. Keep Jobs, Imports and Providers secondary to browsing. Show real capability/status and concise empty states, without repeated administrative slogans.
- ADMIN-02: Keep job monitoring and one metadata-selection destination in the shared compact sidebar. Old new-scrape and refresh URLs resolve to the unified view and retain media scope. The sidebar remains visible while content scrolls; on narrow screens it becomes a horizontal navigation row. Preserve monitoring filters, polling, infinite scrolling, bulk actions, `jobId` and `batchId` deep links. Opening destinations or editing forms never queues work; launched batches link to their progress in monitoring.

## Acceptance

CSV descriptive fields are bootstrap hints for new films. Existing-film imports only apply personal rating/watchlist/bookmark state and dates, plus missing identifiers. They do not replace canonical title/year/summary/artwork, library Added dates, source labels, public scores/vote counts, genres or credits; use an explicit metadata refresh for those. Preview and execution share this policy and preserve manual overrides. Equivalent personal state retained in legacy snapshots or source hints is recognized through a pure local-plugin hook, not reported as a new update merely because a newer canonical field is absent.

Test a fixture with a mock local plugin and missing plugin; validate canonical fields, snapshots and rate guards. Check Git ignores the actual installed private package. Test import twice and compare database/source totals and values. Inspect browser network activity to confirm no scrape calls occur during browse/import testing.
