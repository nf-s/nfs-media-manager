# Details, edits and history

## Requirements

- DETAIL-01: Overview is immediately useful: art, creators, release, source/status, service links, tags, synopsis and key metrics. Important information is not nested in collapsed sections. Use concise tabs: Overview, Tracks (albums), Playlists (albums and tracks), Listening, Sources and Edit where supported. Read source history and raw snapshots on demand within Sources.
- DETAIL-02: Open an item in one inspector over the current view. Internal detail links replace the visible item in the inspector and add to its history. Back, browser history, reload and copied links restore the selected detail and its view settings. **Open page** opens a standalone detail. Clicking filterable metadata applies a filter to the relevant library. Closing restores focus and scroll.
- DETAIL-03: Canonical title, art, source and supported album/film fields can be overridden without overwriting provider snapshots. Show saved/error states and refresh list/detail after saving.
- DETAIL-04: Provider identifier correction belongs in Sources, separate from canonical field overrides in Edit. Re-scrape uses the corrected identifier. Record actor/time/reason; allow clearing an override to reveal the underlying value. Artist identifier corrections are applied by an explicit refresh and retained on success.
- DETAIL-05: History lists timestamp, provider, provenance, status and payload inspection. Every distinct imported/scraped payload is retained. Reimporting an identical source payload is idempotent; do not erase old history.
- DETAIL-06: Select eligible provider rows in Sources to refresh a subset or all eligible sources for the item, with job/progress feedback. Respect active jobs, cooldowns and unavailable providers. No action fires on mount, on viewing history, or on saving a filter. Read-only source tables do not imply scraping or snapshots that the record does not support.
- DETAIL-07: Filterable detail values use the same compact pill treatment, including source and watched status. Artist, director, actor and channel names open their own details with explicit actions to filter the library. Active filter pills share Any / Required / Excluded colors and behavior with browse filters. Shift-click keeps the page/inspector open for adding multiple filters. Do not repeat funnel icons on individual values in details, tables or grids.
- DETAIL-08: Clicking a tag or collection label filters; its adjacent source control never filters. Open a single known collection link directly. Otherwise show a compact popover of relevant, deduplicated links; opening sources reads stored evidence only. Manage tag shows aliases and paginated provenance, distinguishing item origins from those merged elsewhere. Escape closes the nested surface and restores focus without closing media details. Never guess upstream IDs.
- TAG-01: Counts, aliases, merges, provenance and visibility belong to one library. Hide removes a group from display and autocomplete, not stored membership or existing explicit filters. Reimports preserve visibility; a merge involving a hidden group stays hidden until explicitly unhidden. Manage hidden groups separately, with loaded-row and Shift-range selection. See [tag and collection sources](../tag-source-navigation.md).

## Acceptance

Open, edit, inspect history, return to the same scroll location, then deep-link and reload. Test errors and empty history. Mock job execution for corrected identifiers. Verify important content is visible without expanding JSON and raw credentials never appear in history or browser responses.
