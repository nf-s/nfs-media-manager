# Local Scraping Packages

## Location and Loading

Keep private integrations under ignored `.local-plugins/<package>/` or outside the public checkout. Each package should contain a manifest, implementation, README and offline tests. Back up this directory independently or maintain it in a separate private repository. Git does not preserve ignored code when cloning or restoring a public checkout.

Set `MEDIA_PLUGIN_PATHS` in the existing root environment to comma-separated absolute or workspace-relative **entry-file paths**. Build `@repo/media-plugin-sdk` first. Restart the API after changing the configured package list; the registry caches loaded plugins. Do not put private examples in the public environment template.

The registry accepts a default export or named `plugin` export conforming to `MediaProviderPlugin`. It validates the manifest and callable hooks, rejects conflicting provider IDs and skips missing optional entry files with a warning. An installed but invalid package fails explicitly rather than silently presenting an incomplete integration.

## Contract

Use `packages/media-plugin-sdk/src/index.ts` as the authoritative contract. Declare provider identity, display label, media kinds, credentials, hard rate limits and optional browse fields. Credential descriptors can specify environment fallback names; database credentials take precedence. Public server code must not know a private provider's name or credential variables.

`scrapeMediaItem` returns a payload and normalized fields/references. `importLegacyRecord` translates local raw and cleaned records without credentials or network activity. Validate external responses before returning normalized data. Optional browse keys must use the package namespace `plugin.<provider-id>.<field>` and are exposed through the same sorting/range controls as public fields.

Numeric browse fields may declare `rating: { provider, scale, votesKey?, shortLabel?, iconUrl? }` to appear in shared grid, table and detail rating badges. Point `votesKey` to that score's vote-count field; omit it when unavailable, never substitute another provider's count. Keep private labels and icons in the local package. Bundle small raster icons as data URLs to avoid provider requests while browsing; HTTPS icon URLs are also accepted. SVG data URLs and executable schemes are rejected.

Set `rating.compact: true` to include a plugin rating in compact card/row strips. The public film strip otherwise shows only IMDb, Metascore and Letterboxd; details retain all declared ratings. Keep this opt-in and the provider identity in the local manifest, never a private-provider allowlist in public UI code. Runtime icon rendering uses embedded raster data only, even though the contract also accepts HTTPS URLs.

For source navigation, an optional `manifest.sourceNavigation` declares `collectionUrlTemplate` and `tagUrlTemplate`. Templates substitute URL-encoded `{id}` or `{name}` in a path/query, never a host or scheme; only HTTP(S) links without embedded credentials are exposed. Normalized `plugin.<id>.details.collections` entries may contain `{id, name, url?}`. Keep private origins/templates in the ignored package, not public UI code.

An optional pure `readStoredCollections(payload)` hook returns `{id: string, name: string}[]` from existing provider or legacy-record payloads. It receives no secrets or request capability and must never fetch, scrape or mutate anything. Detail reads use it to restore navigation for older imports without reimporting or rewriting snapshots. Malformed or unsupported payloads do not break browsing. Name-only memberships remain filterable and show that their source link is unavailable.

An optional pure `readStoredPersonalState({payload, sourceKind, sourceLabel})` hook interprets retained import evidence as bookmark/watchlist flags and ISO dates. CSV preview and commit use this to recognize equivalent legacy personal state without rewriting canonical metadata or snapshots. The server validates the result against `StoredPersonalStateSchema`; newest retained evidence is preferred, and explicit canonical values take precedence. Return `null` for unsupported payloads. Keep legacy field names and source-label interpretation inside the local package; this hook receives no secrets or network capability and must not perform writes or requests.

## Safety and Maintenance

Set `rateLimit.respectRateLimitHeaders: true` only for providers whose contract uses `X-RateLimit-Limit`, `X-RateLimit-Remaining` and a Unix-second `X-RateLimit-Reset`. This opt-in persists a cooldown when a successful response reports zero remaining and a valid positive limit/future reset; the current result still succeeds. For 429 or explicit API quota errors, a valid future reset extends (never shortens) Retry-After and the minimum cooldown. These headers do not change local request caps, clear access halts or trigger retries. No additional quota-discovery calls are made.

Services such as MDBList distinguish short-window throttles from daily exhaustion. For these, `rateLimit.retryAfterIsAuthoritative: true` uses a valid future Retry-After directly; `rateLimitCooldownMs` becomes the fallback when it is absent or invalid. A daily reset extends the wait only when quota headers confirm zero remaining. Scheduled rate-limit errors do not add the generic repeated-error cooldown, but do not retry automatically or bypass an existing wait. Other providers retain the default minimum-cooldown behavior.

Do not make network requests during module import, registration, file import or normal tests. Every live HTTP call must use `context.request`, not direct `fetch` or a client with hidden retries. The server's Postgres-backed request gate shares spacing, concurrency, optional rolling-hour limits and cooldowns across jobs and credential tests. Server restarts do not reset the budget. Execution remains serialized unless `rateLimit.concurrentRequests: true` explicitly enables the declared `maxConcurrent` in both the HTTP gate and job-item worker pool. MDBList opts in with three concurrent requests and 350 ms between starts; other providers retain their previous throughput. The gate stores independently expiring leases under its provider row lock, releases only the completed request's lease, and blocks cooldown clearing while requests remain in flight.

An optional `rateLimit.fixedWindow: { durationMs, reads, writes }` enforces independent read/write limits in epoch-aligned fixed windows. MDBList uses 300,000 ms, 1,000 reads and 300 writes. Request events retain their classification and timestamp, so independent clients, process restarts and budget edits cannot reset usage. GET counts as read; other methods count as write. No POST batch-read exception is currently used by an adapter. If one is added later, implement a validated explicit exception before using the larger read allowance. Keep these counters independent of the editable hourly/daily budget.

Declare `maxRequestsPerHour`, `rateLimitCooldownMs` and `errorBackoffMs` where needed. HTTP 429 or an explicit API quota message stops a batch and honors the longer of Retry-After and the configured cooldown. Access denial halts requests until explicit credential maintenance. Two unexpected failures stop the batch and cancel queued work for that provider. By default, HTTP 400/5xx backs off and repeated failures apply a 15-minute cooldown. A package can set `errorBackoffMs: 0` and `failureCooldownMs: 0` to disable these generic timed penalties without disabling the two-error stop, spacing or hourly budget. An explicit server Retry-After is still respected; with generic cooldowns disabled, non-rate-limit responses delay the next allowed request rather than setting a quota cooldown. Nothing automatically retries failed items. Optional `maxItemsPerJob` and `requireExplicitSelection` let a package forbid broad jobs regardless of the admin confirmation flag. Other apps sharing an account are outside this process's budget.

An optional `rateLimit.requestBudget: { period: 'hour' | 'day', limit: number }` adds a rolling-hour or UTC-calendar-day budget. `configurableRequestBudget: true` explicitly permits authenticated updates from Providers via `PATCH /api/v1/providers/:provider/budget`. MDBList defaults to 10,000/day and opts in. This does not relax a separately declared `maxRequestsPerHour`, minimum spacing or service cooldown. Usage is derived from persistent request events under the reservation lock; changing period/cap does not reset it. Daily mode resets at midnight UTC. Only the configured budget is overridden; all other safety settings remain plugin-controlled.

Throw `ProviderItemNotFoundError` only after validating a successful response that definitively has no matching item. Never use it for malformed responses, authentication errors, quota messages or HTTP failures. The item remains unsuccessful in job history but does not count toward the provider failure cutoff or create a cooldown. Its log can be marked benign after explicit review. A package may declare exact historical `{ name, message }` pairs in `manifest.reviewableErrors` for old plain `Error` logs; this is not a substring match or a user-editable ignore rule. Transport exceptions and chained errors are not reviewable.

The queue and request gate use the SDK's `isProviderItemNotFoundError` guard rather than constructor identity: local packages can load the built SDK while the development server loads its TypeScript source. Rebuild the SDK and restart the server after updating this contract. A lookup miss must not cancel other items or queued jobs, even when the provider has earlier failures; genuine request failures still use the existing safety cutoff. Deploying a fix does not reset safety state or automatically retry previously cancelled work.

Marking a log benign records the user and timestamp while preserving its original message and stack. It applies only to that occurrence. When every failed item is reviewed and none were cancelled, the job leaves Needs attention; it is never relabeled successful. Review never clears provider safety state, changes budgets, retries work or adds a rule for future failures.

The Providers page shows effective settings, exact reviewable error messages and recent benign reviews. It records dispatched request attempts in `provider_request_event` separately from the rolling safety ledger, with 1-hour, 24-hour and 7-day charts. Blocked requests do not count. Migration preserves the timestamps still present in the old ledger, but older history is incomplete; `history_started_at` marks when complete recording began. URLs, headers, credentials and payloads are not stored in the request chart history.

An authenticated user can explicitly clear an active cooldown from Providers. Confirmation warns that already-queued jobs may resume. Clearing checks the displayed cooldown has not changed, rejects in-flight requests, and records the actor and previous expiry in `provider_cooldown_reset`. It does not clear access denial, request spacing/backoff, failure counters or hourly/daily request usage. A new rate-limit response reinstates its cooldown normally. Dismissing a failed job is separate: it only removes the job from Needs attention and retains all errors and history.

The HTTP gateway is cooperative, not a sandbox for arbitrary installed code. Only load trusted packages that use it. Rate limits do not grant permission for bulk collection: follow the provider's acceptable-use rules. Retain only metadata from API responses, which can include account credentials. Redact secrets before returning a result or logging anything. File-only formats can be declared with `manifest.fileImports` and translated using `importFileRecord` without making any network calls.

Write offline tests for raw and cleaned import shapes, missing identifiers, normalization, failures and request throttling. Live checks are separate, explicitly authorized and limited to a single known item. The public app may display a private package's runtime label and metadata, but private fixtures, keys and source names must never enter tracked code or documentation.
