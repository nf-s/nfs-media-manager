# Film collections

Choose **Films → Collections** to browse stored collections and the number of their films in the library. The workspace fills the available content width. Search by collection name, sort by name, film count or Added, and use **Columns** to choose fields. Added is when the collection was first stored locally. Source icons are optional and hidden by default; showing them resolves provenance only for the requested page. They are actions, not a directory sort or filter field.

The directory reads bounded pages from the server. Search and sorting apply to the complete dataset before the page limit, with stable ties. Rows and the exact count load independently. Keep a viewport of placeholders while counting, then reserve the entire matching result height and fill only the pages near the current viewport. Jumping to a distant position must not download intermediate pages. A failed page retains its placeholders and offers Retry; a failed count does not hide ready rows.

Open a collection to view its films in **Stored position** order. Positions come directly from stored collection membership; missing films are not fetched or inserted and gaps are not renumbered. Equal positions use title and internal ID as stable tie-breakers. Older legacy imports can contain the index of the collection on a film rather than the film's upstream rank, and providers can omit ranks (stored as zero). Those records cannot reconstruct a source order that was never saved. Browsing collections does not scrape providers or modify membership.

Collection names in film grid, list, table and detail views open the collection panel using the canonical membership ID. They push inspector history so Back returns to the film without changing the underlying browse filter or scroll. The table and detail panel separately offer **Filter films**, which opens Browse restricted to that collection. Source links come only from stored provider provenance; missing links are not guessed. The collection panel shares the playlist panel’s resizable width and header actions.

Each film links to its existing detail view. All data columns can be sorted in either direction; **Columns** also exposes artwork, source and Added. Search and multi-select Watched filters appear with the table controls and column header respectively. Filtering and sorting apply to the complete collection before pagination. Choose Stored position ascending to restore the stored order. Counts include only library films, even if a historical collection also contains album memberships.

Collection films support Grid, Details and Table. Grid uses portrait artwork; Details shows a compact image and metadata row. The chosen view is remembered independently of film Browse, and all modes retain the same search, watched filter, sorting, panel links and virtual page cache. Changing mode preserves the visible item rather than loading intervening pages.

`GET /api/v1/collections/browse-page` returns `{ items, page, size, hasMore }` for stored collections containing films. It accepts `q`, `sortBy=name|filmCount|createdAt`, `direction`, `page`, `size` (up to 100) and optional `includeSources=true`. Sources are omitted by default. `GET /api/v1/collections/browse-count` returns `{ totalCount }` for the same name search without reading source payloads. The legacy `GET /api/v1/collections` retains its array response but now returns only the requested bounded page; it accepts the same paging and sort parameters and includes sources by default.

`GET /api/v1/collections/:id` returns the collection and paged films, with `q`, `watchedStates` (a JSON array), `sortBy`, `direction`, `page`, `size` (up to 100) and `includeSources`. The film viewport sends `includeSources=false` so no page traverses the collection's source payloads. Opening Sources separately reads `size=1&includeSources=true`; merely browsing films does not read source evidence. Omitted `includeSources` retains the legacy response. All routes require owner authentication. The existing `playlist` and `playlist_item` tables hold collections; no migration or rescrape is required.

Verification uses synthetic collections in a disposable database, with network access blocked. Coverage includes bounded directory responses, separate counts, page-only provenance, literal name search, global sorting before paging, gaps, equal positions, film-only counts, missing data, invalid queries and authentication. Browser verification checks a distant directory jump, initial and delayed placeholders, retries, bounded DOM, mobile width, collection panel history and nested Grid/Details/Table geometry.
