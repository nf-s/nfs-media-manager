# Album and film collections

Choose **Albums → Collections** or **Films → Collections**. Each directory counts the members in the selected library. The workspace fills the available content width. Search by collection name, sort by name, member count or Added, and use **Columns** to choose fields. Added is when the collection was first stored locally. Source icons are optional and hidden by default; showing them resolves provenance only for the requested page. They are actions, not a directory sort or filter field.

The directory reads bounded pages from the server. Search and sorting apply to the complete dataset before the page limit, with stable ties. Rows and the exact count load independently. Keep a viewport of placeholders while counting, then reserve the entire matching result height and fill only the pages near the current viewport. Jumping to a distant position must not download intermediate pages. A failed page retains its placeholders and offers Retry; a failed count does not hide ready rows.

Open a collection to view its albums or films in **Stored position** order. Positions come directly from stored collection membership; missing films are not fetched or inserted and gaps are not renumbered. Equal positions use title and internal ID as stable tie-breakers. Older legacy imports can contain the index of the collection on a film rather than the film's upstream rank, and providers can omit ranks (stored as zero). Those records cannot reconstruct a source order that was never saved. Browsing collections does not scrape providers or modify membership.

Collection names in album and film grid, list, table and detail views open the collection panel using the canonical membership ID. They push inspector history so Back returns to the originating item without changing the underlying browse filter or scroll. The table and detail panel separately offer **Filter albums** or **Filter films**, which opens Browse restricted to that collection. The header offers **Open on** for each distinct source destination supported by stored provenance. These destinations are also available under Sources. The collection panel shares the playlist panel’s resizable width and header actions.

Each collection entry links to its detail view. All data columns can be sorted in either direction; **Columns** also exposes artwork, source and Added. Search and multi-select Watched filters appear with the table controls and column header respectively. Collection entries default to the library scope. **Include outside library** shows known entries, and **Filters** offers **Outside library** and discovery sources. Discovery sources apply only to outside items. Filtering and sorting apply before pagination. Choose Stored position ascending to restore the stored order. **Show in Films** or **Show in Albums** opens Browse with the same library and discovery scope, search, a single chosen Watched state, the view and any order Browse also has. Counts use the selected media type and scope.

Collection films support Grid, Details and Table. Grid uses portrait artwork; Details shows a compact image and metadata row. The chosen view is remembered independently of film Browse, and all modes retain the same search, watched filter, sorting, panel links and virtual page cache. Changing mode preserves the visible item rather than loading intervening pages.

`GET /api/v1/collections/browse-page` returns `{ items, page, size, hasMore }` for stored collections containing films. It accepts `q`, `sortBy=name|filmCount|createdAt`, `direction`, `page`, `size` (up to 100) and optional `includeSources=true`. Sources are omitted by default. `GET /api/v1/collections/browse-count` returns `{ totalCount }` for the same name search without reading source payloads. The legacy `GET /api/v1/collections` retains its array response but now returns only the requested bounded page; it accepts the same paging and sort parameters and includes sources by default.

`GET /api/v1/collections/:id` returns the collection and paged films, with `q`, `watchedStates` (a JSON array), `sortBy`, `direction`, `page`, `size` (up to 100) and `includeSources`. Album and film collection endpoints accept `libraryScope=library|outside|all`, optional comma-separated `discoverySources`, and `discoverySourceMode=any|all`. The viewport sends `includeSources=false` so no page traverses the collection's source payloads. Opening a collection reads `size=1&includeSources=true` once for its header and Sources tab. Scrolling through members reuses that result. Omitted `includeSources` retains the legacy response. All routes require owner authentication. The existing `playlist` and `playlist_item` tables hold collections.

The album directory uses `GET /api/v1/album-collections/browse-page` and `/browse-count`, with `albumCount` as its count sort. `GET /api/v1/album-collections/:id` returns paged albums with their credited artist names, release dates, durations and stored positions. Album detail links include `mediaType=album`. Existing film collection URLs continue to open films.

Verification uses synthetic collections in a disposable database, with network access blocked. Coverage includes bounded directory responses, separate counts, page-only provenance, literal name search, global sorting before paging, gaps, equal positions, film-only counts, missing data, invalid queries and authentication. Browser verification checks a distant directory jump, initial and delayed placeholders, retries, bounded DOM, mobile width, collection panel history and nested Grid/Details/Table geometry.
