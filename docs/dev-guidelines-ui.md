# UI Guidelines

## Stack

- `apps/web` uses `Next.js App Router`.
- Client-side data fetching goes through `TanStack Query`.
- The [design system](design-system/README.md) is the only source of interface design. Build screens from the shared components in [`packages/ui/src/components/ds`](../packages/ui/src/components/ds) and [`packages/ui/src/components/ui`](../packages/ui/src/components/ui), styled only with the `--ds-*` tokens in [`tokens.css`](../packages/ui/src/design-system/tokens.css). The stylesheets in `packages/ui/src/styles` hold page layout only, and dates, times, counts and durations are formatted by [`packages/ui/src/lib/format.ts`](../packages/ui/src/lib/format.ts). A new visual element or variant follows the approval process in [AGENTS.md](../AGENTS.md).

## Page Pattern

- Protected pages live under the App Router admin layout.
- Use [`apps/web/components/page-auth-guard.tsx`](../apps/web/components/page-auth-guard.tsx) for server-side auth gating.
- Use [`apps/web/components/providers.tsx`](../apps/web/components/providers.tsx) for the shared query client and config context.
- Keep list state in URL search params when practical so views are shareable and recoverable.
- Use `SectionSidebar` and `SectionWorkspace` for secondary navigation where a section still has one, as in Imports and Tags. Route destinations use links; in-page selections use buttons. Above 700px the sidebar is placed in the navigation rail under the main navigation (`useRailSlot`); on phones it is a scrolling segmented row above the content. Keep the shell bounded and scroll only the rail section/content regions. Jobs monitoring retains its own infinite-scroll region.
- The shell is a navigation rail beside one white content panel; on phones the rail becomes a top row (library, refresh, account, sign out) and a bottom tab bar. The Jobs and Providers tabs carry their counts on the corner, and the Jobs count opens Activity above the bar. Filters and item details open as the same sheet. Browse places its active filters in the rail above 700px. With Spotify playback connected, a player dock spans the bottom of the shell once something is played or queued, or while the account plays on another device; drawers end above it, and on phones it is a mini-player above the tab bar.

## Data Fetching

- Fetch server data through [`apps/web/utils/api.ts`](../apps/web/utils/api.ts) and validate responses with shared Zod schemas.
- Keep mutations in client components or dedicated hooks. Invalidate affected query keys after success.
- Use the shared four-hour freshness and 24-hour inactive retention defaults for stored data, including browse pages and filter suggestions. Render cached data during background refreshes and retain it on refresh errors. Do not reset or remove queries merely to refresh them.
- The shell's Refresh control invalidates cached reads, refetches mounted queries and leaves inactive queries to reload when opened. Cache contents stay in memory; reloading the page or signing out clears them. Active jobs and imports keep short polling intervals; the activity monitor checks every 30 seconds when idle and invalidates affected views when work changes.
- Do not store provider secrets in client state beyond transient form input.

## Interaction

- Browse pages must handle loading, empty, and populated states.
- Every server-backed collection or item directory, table, list, grid and detail section uses bounded server pagination. This includes endpoints that previously returned arrays: an unpaginated response is a missing implementation, not an exemption. Search and sort before applying the server limit; never download the directory to filter it in the browser. Reserve the full matching scroll extent when the total is known. Render same-size placeholders for unloaded slots, load only the viewport and nearby pages, and offer Retry within the view. See the [secondary table pattern](secondary-tables.md).
- Detail pages must expose history, provider references, overrides, and re-scrape actions.
- Job creation UI must remain conservative by default and clearly signal broad-run confirmation.
- The sign-in form shows "Could not sign in. Check the email and password." when sign-in fails.

## Visual Direction

- Prefer compact, high-density browsing with high-contrast text and subtle dividers. Do not trade density for whitespace.
- Cool grey page (`--ds-page`) with light grain, flat white panels, near-black text and slate accents. No green. Success is neutral slate, failure muted red, running/queued/needs-attention amber. Provider rating marks are neutral: a short source label and the score in the monospace face (`Rating`). Ratings on scales up to 10 always show one decimal (`8.0`); larger scales show whole numbers. The detail overview shows each rating as a rating card.
- Modest radii: panels 10–12px, controls 6–8px, artwork 4–6px, pills fully rounded. Hairline dividers (`--ds-line`, `--ds-line-soft`) instead of nested bordered cards.
- Use blur only on bars that content scrolls under, popovers and sheets. Never on repeated elements such as artwork overlays or on full-screen backdrops: it is slow in Firefox.
- No gradients, decorative banners or repeated administrative labels.
- Use shared buttons, inputs and other primitives. Do not wrap every group in a card.
- Keep grids artwork-first, lists thumbnail-led and tables compact. Use `BrowseToolbar` for primary and embedded views that offer Grid, List and Table. It places search before the sort picker, sort direction, view switcher, the Filters button and result count. Keep the same compact controls in every view. Filters opens the shared drawer with collapsible sections for the controls available in the current view: View first, with grid size (Grid only) and the list's own options (`viewOptions`), then Columns in Table and the filters. Primary Browse puts active filter chips in the rail or mobile filter row. A list inside a detail that has a Browse page's items is that page's browser with a `useEmbeddedBrowse` host (`hooks/useBrowseHost.ts`): the same controls with `compact`: the Filters button shows its icon and count, and one line under the toolbar (`FilterLine`) holds the chips, the count and the **Show in** link from the toolbar's `end` slot. Other lists inside a detail also pass `compact`; with no link or chips their count stays on the toolbar.
- Browse screens are built from `Toolbar` (search, `SortPicker`, direction, `Segmented` view switch, the Filters button, `ToolbarCount`), `CardGrid`/`Card`, `List`/`ListRow` (48px rows, 40px art) and the one table. Shared helpers: `BrowseToolbar`, `BrowseFilterPill`, `BrowseTagBadges` (`max`), `MediaArt`/`MediaThumb` (artwork shape and placeholder per kind), `BrowseSortHead` (sortable, resizable header) and the row-height constants `tableRowHeight` (32), `tableHeaderHeight` (28) and `listRowHeight` (48) from `hooks/useVirtualTable`. Card geometry for virtual grids comes from `mediaGridGeometry` or `itemGridGeometry` with `gridCardMin(kind, density)`, which mirror `.ds-grid` gaps and padding. Default views come from `defaultBrowseView` and the density from `useGridDensity` (Browse) or `useNestedGridDensity` (details), which start compact on phones.
- Apply this Browse pattern to every primary library, including Artists. Use Tracks as the working reference and reuse `AiSearch`, `BrowseFilterAutocomplete`, filter chips, ranges, view switching and virtual paging. Field suggestions, Any/Required/Exclude modes, AI search, sorting and URL state are baseline behavior, not optional per-page additions. Metadata selection uses the same search control and semantics with its provider freshness filters. An exact count must not delay visible rows.
- Start server requests for autocomplete suggestions with `useBrowseFacets` on search focus or when there is a draft. Keep facet requests off the initial results load and debounce changes to the draft.
- Open details and User without losing browse state or scroll. `DetailInspector` renders every detail, job and tag in `MediaInspector`: a remembered desktop width, adjustable by dragging the left edge or using the focused separator's arrow keys. Its top bar holds Back (when there is history), the kind of the open item, **Open page** and Close. On phones the panel stays within the viewport, with horizontal scrolling inside wide tables and tabs; swipe down from the bar, use Close, or press Escape to dismiss it. The phone player opens in the same `MediaInspector`; do not build a separate sheet for it. Show useful information immediately and keep provider identifiers, refresh actions, history and stored snapshots in Sources. Each provider is one source row that opens in place.
- Build every detail from `components/detail-frame.tsx` and the design-system components: `DetailHeader` with `DetailArt`, `DetailTabs` with `useDetailTab` (URL state, older tab aliases), `Section`, `Stats`, `Facts`, `KeyValues`, `Pills`/`FilterPill`, and `State`/`Notice`/`Skeleton` through `CreatorDetailState` for loading, error and stale states. Header play uses `AlbumHeaderPlay`, `TrackHeaderPlay` or `PlaylistPlayButton` (`components/detail-play.tsx`, `playlist-detail.tsx`); rows inside a detail use `TrackRowPlay` or `AlbumPlay`. Tables inside a detail are the one table; an album's track list is a compact table (number, title with the play pair, duration, scrobbles, plus Artists on a compilation) with the first 20 tracks and **Show all**. Standalone pages wrap the detail in `DetailPage`.
- Item and collection names open the shared inspector and push its back history. Collection names in film cards, lists, tables and details use their stored collection membership ID. Keep **Filter films** separate from opening collection details.
- Grid artwork stays clean: only the hover/focus play pair and one small state badge sit on it. Title, creator, a meta line (year and one rating or the sorted value) and a tags line sit under it; in Albums and Films, Filters > View > On cards controls the rating, sorted value and tags line. Tags are pills with a `+N` count in every view, never a scrolling strip. The filter drawer closes on Escape or an outside click and restores focus to its trigger. Remaining toolbar popovers (`details.browse-popover`) open one at a time and close on Escape or an outside click.
- Keep Play immediately followed by Add to queue wherever music playback is available. Keep both controls visible on phones and group them separately from title and service links. Every play control renders the shared `PlayPair` (rows and cards) or `PlayHeaderButtons` (detail headers) through `play-controls.tsx`. The row number of a playlist or album track sits before the pair.
- Use the design-system `Pill` for clickable filters in details, including source and watched values, with the active filter's Any / Required / Excluded mode. Keep table and grid values compact without repeated filter icons; their filtering behavior and keyboard access must remain intact. Do not place a source icon beside each tag; tag provenance lives in Sources and in the tag drawer.

## Secondary tables

Use the [secondary table pattern](secondary-tables.md) for shared sortable headers and an unframed scroll container. Primary and embedded results have no extra rounded outline around the table, list or individual list rows, and no divider below the search/filter toolbar. Keep ordinary row and column-header separators. Where the results are always tabular, use the design-system `Toolbar` immediately above the table in the order search, result count, then Columns in its own upper-right slot (`SecondaryDataTable` builds it; other tables use `SecondaryTableToolbar`, which renders the same `Toolbar`). Table-wide actions and active filter chips sit above that toolbar. Album, film and artist metadata selection use `MetadataSelectionToolbar` to preserve this order. Put multi-select categorical filters and range controls in their column headers. Select eligible rows with a tri-state header checkbox. Where a server-backed workflow supports selecting the entire matching result set, offer an explicit **Select all matching** action in the toolbar after the count and label the header checkbox for its current loaded-row or saved-selection scope. Selected-row actions and confirmations belong in the attached selection bar (`ds-selectbar`, through `SecondaryTableSelectionBar` or `TableSelectionBar`) below the scrolling rows. The bar appears only while something is selected or an action has a result to report; import previews keep "0 selected of N". Provide search and filters where they help, including hiding already imported items in previews. Playlists, film collections and other secondary workspaces always fill the available content width.

Every table has set column widths: a default `width` per column, fixed layout from `useTableColumns().layout` (or `useTableWidths` where there is no column chooser) and a width handle on each data column's header, saved per table. Do not leave a table on automatic layout: its columns move as rows load. One column takes the room that is left: the one marked `fill`, otherwise the last data column.

Offer Columns only when there are more than three available columns in a secondary table. Smaller tables show every column and omit redundant controls. Keep chosen columns accessible through horizontal scrolling on phones. Search, filter and sort raw values across the complete result set before pagination. Selection, artwork and action columns are exempt from sorting. Reset selection and pagination when the displayed results change. Verify primary and embedded views side by side at desktop and phone widths with menus open, since inherited page styles can change toolbar sizing. The guide lists covered views, component responsibilities, date semantics and verification requirements.

Keep ordinary rows to one line wherever possible and never more than two. Use bounded shared cells with ellipsis, readable primary values and full text tooltips; move long explanations, errors and change lists into the shared eye-button details popover, available by hover, focus or tap. Keep actions on one line and label every icon-only button. Job diagnostics belong in the shared job details inspector. Loading/error states are exceptions. Check actual row heights with verbose synthetic fixtures at desktop and phone widths.
